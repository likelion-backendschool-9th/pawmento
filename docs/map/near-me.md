# 정보 지도 내 위치 주변 보기와 가까운 순 목록

관련 이슈: [#226](https://github.com/likelion-backendschool-9th/pawmento/issues/226), 상위 [#172](https://github.com/likelion-backendschool-9th/pawmento/issues/172) ([정보 지도 계획](animal-places.md)), 함께 쓰는 [#195](https://github.com/likelion-backendschool-9th/pawmento/issues/195) ([검색 계획](place-search.md))

## 한눈에
- 끝나면: 보호자가 정보 지도의 "내 위치" 버튼을 눌러 지도를 내 위치로 옮기고, 내 주변 병원·미용·보호센터를 가까운 순 목록과 거리로 본다. 반경(500m·1km·3km)을 바꿀 수 있다.
- 결정 필요: 없음. 서버는 바꾸지 않고 화면(프론트엔드)만 만든다([정한 것](#정한-것)).
- 규모: 2단계(PR 2개: 문서, 화면)

시안: 정보 지도 검색·내 주변 시안(⑤ 내 위치 주변, ⑥ 위치 권한이 꺼져 있을 때, ④-2 지역·역 기준 목록). 시안 속 장소 이름·거리는 예시다.

## 1. 내 위치로 이동 (#226-R1)
버튼을 누를 때만 위치를 묻는다. 허락하면 지도가 내 위치로 가고 내 위치가 점으로 보인다. 위치는 한 번 읽는 값이고 계속 따라가지 않는다.

#226-S1 처음 누를 때 설명 [직접]
- Given 이 기기에서 "내 위치"를 처음 누른다
- When  버튼을 누른다
- Then  브라우저 권한 창보다 먼저 우리 안내 시트가 뜬다: "내 주변 장소를 찾으려고 현재 위치를 써요. 위치는 저장하지 않아요." 그리고 "계속"과 "나중에"가 있다
- When  "계속"을 누른다
- Then  브라우저의 위치 권한 창이 뜬다
- When  "나중에"를 누른다
- Then  시트가 닫히고 아무것도 바뀌지 않는다. 지도 화면에 들어오자마자 권한을 묻지 않는다
- Given 이미 허락했다
- Then  안내 시트 없이 바로 위치를 읽는다

#226-S2 허락하면 이동한다 [직접]
- Given 위치를 허락했다
- When  위치를 읽는다
- Then  읽는 동안 버튼이 "찾는 중"으로 바뀌고 다시 눌러도 겹쳐 읽지 않는다
- Then  지도가 내 위치로 옮겨 가고(확대 수준은 500m 반경이 보이게 맞춘다) 초록색 점과 정확도 범위(원)가 보인다. 그 영역의 장소가 평소처럼 보인다(#172-S16)
- Then  방향 표시는 없다. 점은 내 위치만 나타낸다
- When  버튼을 다시 누른다
- Then  위치를 다시 읽어 그 위치로 옮긴다. 점은 그동안 움직이지 않는다

#226-S3 위치를 읽지 못할 때 [직접]
- Given 위치를 허락했지만 읽지 못했다(시간 초과 10초, 위치를 알 수 없음, 이 브라우저가 위치를 지원하지 않음)
- When  버튼을 눌렀다
- Then  "위치를 찾지 못했어요. 잠시 뒤 다시 눌러 주세요"가 보이고 지도는 그대로다. 지원하지 않는 브라우저면 "이 기기에서는 내 위치를 쓸 수 없어요"가 보이고 버튼은 흐려진다

#226-S4 권한을 거부했을 때 [직접]
- Given 위치 권한을 거부했거나 이 사이트의 위치가 꺼져 있다
- When  버튼을 누른다
- Then  "위치 권한이 꺼져 있어요"와 이유("내 주변을 가까운 순으로 보려면 위치가 필요해요"), 해결 방법("설정에서 이 사이트의 위치를 허용해 주세요")이 보인다. 지도와 검색은 그대로 쓴다
- Then  서울 같은 기본 위치로 몰래 옮기지 않는다
- Then  "설정 방법 보기"를 누르면 기기별(iPhone, Android) 안내가 보인다. 설정을 바꾼 뒤 버튼을 다시 누르면 다시 시도한다

## 2. 가까운 순 목록 (#226-R2)
내 위치(또는 정한 기준점)에서 가까운 순으로 목록을 만든다. 서버는 바꾸지 않는다. 목록은 지도 화면이 움직일 때마다 하는 영역 조회(#172-S16)를 쓰지 않고, **기준점을 가운데로 한 영역(반경만큼의 정사각형)을 기존 `GET /maps/places`로 따로 조회한다.** 이 조회는 영역 가운데에서 가까운 것부터 500개를 주므로(#172-S12) 가까운 곳이 빠지지 않는다. 목록 조회는 기준점이나 반경이 바뀔 때만 다시 하고, 지도를 움직이거나 장소를 눌러 지도가 옮겨 가도 목록은 바뀌지 않는다. 지도의 마커는 보이는 영역 기준이고 목록은 반경 안이라 개수가 다를 수 있다.

#226-S5 가까운 순과 거리 [테스트·직접]
- Given 내 위치가 정해져 있고 영역 안에 장소 6곳이 있다
- When  목록을 본다
- Then  내 위치에서의 직선거리(Haversine) 가까운 순으로 보이고 장소마다 거리가 붙는다. 거리는 올림해서 보인다. 990m까지는 10m 단위로 올린 `140m`이고, 991m부터는 100m 단위로 올린 소수점 한 자리 `1.0km`, `1.2km`다(10m 단위로 올리면 991~999m가 `1000m`가 되므로 그때부터 km로 바꾼다). 거리가 같으면 이름순이다
- Then  목록 위에 "내 주변 가까운 순"과 "내 위치에서 반경 500m · 6곳"이 보인다. 지도의 점과 같은 기준이다
- [테스트] 거리 계산, 정렬, 반경으로 거르기, 거리 글자 만들기는 순수 로직 테스트로 확인한다(경계: 정확히 반경 위, 거리가 같음, 좌표가 같음, 거리 글자는 `990`→`990m`, `991`→`1.0km`, `1000`→`1.0km`, `1001`→`1.1km`, `1200`→`1.2km`)

#226-S6 반경 바꾸기 [테스트·직접]
- When  반경을 500m, 1km, 3km 중에서 고른다
- Then  그 반경 안의 장소만 **목록**에 보이고 개수 문구가 바뀐다. 처음은 500m다. 반경에 따라 지도 확대 수준도 맞추지만, **지도의 마커는 반경으로 거르지 않고** 지도 화면의 영역 조회(#172-S16) 결과 그대로 보인다(R2의 "마커는 보이는 영역 기준, 목록은 반경 안"과 같다)
- Given 500m 안에 장소가 없다
- Then  "반경 500m 안에는 없어요"와 "1km로 넓혀 보기" 버튼이 보인다. 3km에도 없으면 "내 주변에는 아직 없어요. 지도를 옮겨 찾아보세요"다

#226-S7 많아서 잘릴 때 [직접]
- Given 목록용 조회(기준점을 가운데로 한 반경 3km 영역)에서 장소가 500개를 넘어 서버가 `truncated=true`를 준다
- Then 서버가 가운데(내 위치)에서 가까운 500개를 주므로 가까운 곳이 빠지지 않는다. 목록 아래에 "더 있어요. 반경을 줄여 보세요"가 보인다
- Then 영역은 사각형이라 반경(원) 밖의 장소가 섞이면 화면에서 반경으로 한 번 더 거른다

#226-S8 목록에서 고르기 [직접]
- When  목록의 장소를 누른다
- Then  지도가 그 장소로 옮겨 가고 마커가 선택되며 장소 카드가 열린다(#172-S17). 내 위치 점과 기준은 그대로다. 목록은 지도와 따로 조회한 것이라 지도가 옮겨 가도 다시 조회하지 않고 그대로다

#226-S9 기준을 바꾸는 다른 동작과 함께 쓰기 [테스트·직접]
- Given 목록의 기준은 **가장 최근에 정한 지점**이다
- When  "내 위치"를 누른다
- Then  기준이 내 위치이고 문구는 "내 위치에서"다
- When  검색에서 지역·지하철역을 골라 이동한다([#195-S17](place-search.md))
- Then  기준이 그 지점이고 문구는 "강남역에서"다. 내 위치 점은 지도에 그대로 있을 수 있다
- When  지도를 손으로 옮기기만 한다
- Then  기준은 바뀌지 않고, 목록도 바뀌지 않는다(목록은 지도와 따로 조회한다). 거리는 마지막으로 정한 기준에서 계산한다
- Given 기준이 아직 한 번도 정해지지 않았다
- Then  목록은 별도 조회 없이 지도 화면 영역의 조회 결과를 "이 지역 장소 N곳"으로 보여 주고 거리는 없다. 이때만 지도를 움직이면 목록이 따라 바뀐다
- [테스트] 기준 지점을 정하는 규칙은 순수 로직 테스트로 확인한다

#226-S10 위치는 저장하지 않는다 [직접]
- When  내 위치를 읽는다
- Then  위치는 이 화면의 메모리에서만 쓰고 저장하지 않는다. 브라우저 저장소나 서버에 쓰지 않는다
- Then  단, 영역 조회 요청에는 내 위치를 가운데로 한 영역(위도·경도 범위)이 담긴다. 서버는 이 값을 장소를 찾는 데만 쓰고 저장하지 않는다. 애플리케이션 로그뿐 아니라 서버 앞의 프록시(nginx)와 Cloudflare 요청 기록에 영역 값이 남는지는 구현 전에 확인한다([가정](#가정))

## 범위 밖
- 길찾기, 이동하는 동안 실시간 위치 따라가기, 위치 기록 저장
- 내 위치의 방향(나침반) 표시. 기기 방향 권한이 따로 필요하다.
- 서버의 "중심과 반경으로 가까운 순 조회"와 PostGIS. 영역 조회로 충분해서 하지 않는다([정한 것](#정한-것)).
- 지역·지하철역 검색 ([#195](place-search.md))

   - 검색 화면([#195](place-search.md))과 같은 파일(`PlacesScreen.tsx`)을 고치므로 병합 순서에 맞춰 rebase한다.

## 정한 것
- **서버를 바꾸지 않는다.** 기준점을 가운데로 한 영역을 기존 `GET /maps/places`로 **지도 조회와 따로** 조회하고, 화면에서 거리 계산·정렬·반경 거르기를 한다. 이 조회는 가운데에서 가까운 500개를 주므로 가까운 곳이 빠지지 않는다. (#226)
- 처음 "내 위치"를 누를 때 우리 안내를 먼저 보이고 그다음에 브라우저 권한을 묻는다. 거부당하면 같은 기기에서 다시 묻기 어려워서, 이유를 먼저 알려 허락할 사람이 거부하지 않게 한다. 화면에 들어오자마자 묻지 않는다. (#226)
- 권한이 없거나 위치를 못 읽어도 막다른 길로 두지 않는다. 이유와 해결 방법을 알리고 지도와 검색은 그대로 쓴다. 기본 위치로 몰래 옮기지 않는다. (#226)
- 위치는 저장하지 않는다. 읽은 값은 이 화면에서만 쓴다. (#226)
- 거리는 지도 위의 직선거리다. 도로를 따라 걷는 거리가 아니다. 문구에 "걸어서 N분" 같은 말을 쓰지 않는다. (#226)
- 반경은 500m(처음), 1km, 3km다. (#226)

## 가정
- 위치를 읽는 값: 정확도 우선 끔, 시간 초과 10초, 1분 안에 읽은 값은 다시 쓴다. 동네 단위 거리를 보여 주는 용도라 배터리를 아끼는 쪽으로 잡았다. 써 보고 바꿀 수 있다.
- 서버를 바꾸지 않는 결정은 영역 조회가 충분히 빠르다는 가정에 기대어 있다. 반경 3km 조회가 느리거나 잘림이 잦으면 서버에 "중심과 반경으로 가까운 순 조회"를 더하고, 그때 실제 데이터(장소 약 1.5만 곳)로 시간을 재서 100ms 이하면 PostGIS 없이 근사 거리식으로, 초과하면 인덱스 조정 뒤 PostGIS를 검토한다.
- 요청 로그에 영역 값(내 위치 주변)이 남는지 구현 전에 확인한다. 남으면 위치를 저장하지 않는다는 문구와 맞는지 다시 정한다.
- 구현 전에 확인할 것: 홈 화면에 추가한 앱(PWA)에서 위치 권한이 얼마나 유지되는지(iPhone). 확인한 뒤 S1의 안내 시트를 보여 줄 때를 정한다.

## 참고
- 브라우저 위치(Geolocation)는 HTTPS(또는 `localhost`)에서만 쓸 수 있다. 개발 서버는 HTTPS라 쓸 수 있다.
- 거리 계산은 Haversine이다. 이 앱의 범위(국내, 수 km)에서 오차는 무시할 수 있다.
- 영역 조회가 영역 가운데에서 가까운 순으로 500개를 주는 규칙은 [#172-S12](animal-places.md)다.
- 위치 정확도가 낮을 때(수백 m 이상)는 점 주위의 원이 커진다. 거리 숫자는 그대로 보이지만, 원이 크다는 것이 그 숫자가 정확하지 않을 수 있다는 신호다.
