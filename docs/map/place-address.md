# 정보 지도 장소 카드의 가려진 주소 보완

관련 이슈: [#239](https://github.com/likelion-backendschool-9th/pawmento/issues/239), 상위 [#172](https://github.com/likelion-backendschool-9th/pawmento/issues/172) ([정보 지도 계획](animal-places.md)), 좌표를 주소로 바꾸는 기존 기능 [#19](memory-location.md)

## 한눈에
- 끝나면: 정보 지도에서 주소가 `*`로 가려진 병원·미용 장소를 눌렀을 때, 카드에 좌표로 찾은 도로명 주소와 건물번호가 보이고 "주소 복사"로 지도 앱에서 건물을 찾을 수 있는 주소가 복사된다. 찾지 못하면 원래 주소가 그대로 보인다.
- 결정 필요: 서버 메모리에 조회 결과를 잠깐 두는지(네이버 약관 확인 뒤), 카드에 "좌표로 찾은 주소" 안내 문구를 둘지, 네이버 호출량을 어떻게 막을지([정하지 않은 것](#정하지-않은-것)).
- 규모: 3단계(PR 3개: 문서, 서버, 화면)

배경: 행정안전부 인허가 원본은 주소 일부를 `*`로 가려서 내려준다(예: `서울숲*길 **-**, ***동 *층 ***호 (성수동*가, 갤러리아 포레)`). 가려진 글자는 원본에 없어서 복원할 수 없다. 그대로 보이면 복사한 주소로 지도 앱에서 찾을 수 없다. 장소마다 좌표는 정확하므로 좌표로 도로명 주소와 건물번호를 얻는다. 층·호는 어떤 방법으로도 알 수 없다.

## 1. 가려진 주소를 좌표로 찾아 보이기 (#239-R1)
장소의 주소에 `*`가 있을 때만, 그 장소를 눌러 카드를 열었을 때 한 곳을 서버에서 조회한다. 조회는 서버가 그 장소의 좌표로 하고, 화면은 좌표나 키를 다루지 않는다.

#239-S1 가려진 주소를 찾은 주소로 보인다 [테스트·직접]
- Given 장소의 주소에 `*`가 있고 서버에 네이버 키가 설정되어 있다
- When  그 장소를 눌러 카드를 연다
- Then  카드의 주소 자리에 좌표로 찾은 도로명 주소와 건물번호가 보인다: `서울특별시 성동구 서울숲2길 32-14`
- Then  원본 괄호 안의 건물 이름 중 `*`가 없는 말은 뒤에 붙는다: `… 32-14 (갤러리아 포레)`. `성수동*가`처럼 `*`가 든 말은 붙이지 않는다
- Then  찾는 동안에는 원래 주소가 보이고, 찾으면 바뀐다. 카드가 열리는 것을 기다리게 하지 않는다
- Then  층·호는 보이지 않는다. 원본에 없는 값을 만들지 않는다
- [테스트] 건물 이름에서 `*`가 든 말과 층·호 표시(`1층`, `지하1층`, `301호`)를 빼는 규칙, 도로명 주소와 건물번호 조립, `*` 판정(주소의 어느 위치든 `*`가 있으면 가려진 주소)은 순수 로직 테스트로 확인한다

#239-S2 가려지지 않은 주소는 조회하지 않는다 [테스트]
- Given 장소의 주소에 `*`가 없거나 주소가 비어 있다(보호센터 포함)
- When  카드를 연다
- Then  네이버를 부르지 않고 원본 주소를 그대로 보인다. 호출을 아끼고 원본이 온전한 주소를 바꾸지 않는다

#239-S3 찾지 못하면 원래 주소를 그대로 보인다 [테스트·직접]
- Given 서버에 네이버 키가 없거나, 네이버 호출이 실패·시간 초과(연결 1초·응답 2초)이거나, 좌표에 해당하는 주소가 없다
- When  가려진 주소의 장소 카드를 연다
- Then  원래 주소(`*` 포함)가 그대로 보이고, 카드의 다른 정보(전화, 운영 시간, 출처)와 "주소 복사"는 평소처럼 동작한다. 오류 문구를 따로 보이지 않는다
- Then  실패해도 같은 카드를 다시 열 때 다시 시도한다

#239-S4 한 번 찾은 주소는 같은 화면에서 다시 부르지 않는다 [테스트]
- Given 이 화면에서 한 장소의 주소를 이미 찾았다
- When  같은 장소를 다시 눌러 카드를 연다
- Then 서버를 다시 부르지 않고 찾은 주소를 바로 보인다. 화면을 닫거나 새로 고치면 처음부터다. 브라우저 저장소에는 남기지 않는다

#239-S9 도로명 주소가 없으면 지번으로 대신하지 않는다 [테스트]
- Given 네이버 응답에 도로명 주소(`roadaddr`)는 없고 지번 주소(`addr`)만 있다
- When  가려진 주소의 장소 카드를 연다
- Then  `{ "address": null }`이고 원래 주소가 그대로 보인다. 지번을 성공으로 돌려주지 않는다. S1이 약속한 것은 도로명과 건물번호이고, 지번에는 건물번호가 없어 가려진 원본보다 나아졌다고 보기 어렵기 때문이다
- 일기 위치의 주소 조회(#19)는 지금처럼 도로명이 없으면 지번으로 돌아간다. 두 기능이 같은 외부 호출을 쓰되 결과를 받아들이는 기준이 다르므로, 이 이슈는 도로명만 돌려주는 입력을 따로 둔다([정한 것](#정한-것))

#239-S10 카드를 바꾼 뒤 늦게 온 응답은 쓰지 않는다 [테스트]
- Given A 장소의 주소를 찾는 중이다
- When  B 장소를 눌러 카드를 바꾸고, 그 뒤에 A의 응답이 도착한다
- Then  B 카드의 주소와 "주소 복사" 값은 바뀌지 않는다. 응답은 장소 id에 묶어 저장하고, 카드는 자기 장소 id의 값만 읽는다
- Then  A 장소로 돌아오면 A의 찾은 주소가 보인다(S4)
- [테스트] 요청 순서를 바꿔 A→B 전환 뒤에 A의 응답이 도착하는 경우를 만들어 B의 표시·복사 값이 유지되는지 확인한다

## 2. 복사는 보이는 주소로 한다 (#239-R2)

#239-S5 주소 복사 [직접]
- Given 카드에 찾은 주소가 보인다
- When  "주소 복사"를 누른다
- Then  카드에 보이는 주소가 복사된다(`*` 없음). 지도 앱에 붙여 넣으면 건물이 찾아진다
- Given 찾지 못해 원래 주소가 보인다
- Then  원래 주소가 복사된다. 있는 그대로 복사하고 임의로 바꾸지 않는다

## 3. 조회 API와 저장 (#239-R3)
화면이 장소 id만 보내고 서버가 좌표를 읽는다. 로그인한 회원만 부를 수 있다. 결과를 DB에 저장하지 않는다.

#239-S6 조회 API [테스트]
- 경로: `GET /api/v1/maps/places/{placeId}/address`. 응답은 `{ "address": "…" }`이고 찾지 못했으면 `{ "address": null }`이다. 200이다
- Given 로그인하지 않았다
- Then  401이다
- Given 없는 장소 id이거나 양의 정수가 아니다
- Then  404이거나 400이고 네이버는 불리지 않는다
- Given 장소의 주소에 `*`가 없다
- Then  `{ "address": null }`이고 네이버는 불리지 않는다(S2)
- Then  요청에서 좌표나 주소를 받지 않는다. 누구든 아무 좌표나 넣어 네이버 호출을 쓰지 못하게 하기 위해서다

#239-S7 조회 결과를 저장하지 않는다 [테스트]
- When  주소를 조회한다
- Then  `places` 테이블의 주소와 좌표는 바뀌지 않고, 조회한 주소는 어디에도 저장하지 않는다. 원본 가져오기(#172)가 주소를 갱신해도 서로 영향을 주지 않는다
- 로그에는 키와 좌표를 남기지 않는다. 실패 종류만 남긴다

#239-S8 예시 데이터는 조회하지 않는다 [직접]
- Given 데모 계정이거나 개발용 예시 장소(`NEXT_PUBLIC_PAWMENTO_MOCK=1`)다
- When  가려진 주소의 예시 장소 카드를 연다
- Then  서버를 부르지 않고 예시 주소가 그대로 보인다

## 범위 밖
- 층·호 복원. 원본에 없다.
- 조회 결과를 DB에 저장하거나 `places`의 주소를 덮어쓰는 것. 네이버 약관을 확인하기 전에는 하지 않는다.
- 목록(마커 위 말풍선, 내 주변·검색 목록)의 주소 보완. 카드에서만 찾는다. 목록에서 여러 곳을 한꺼번에 부르면 호출이 크게 늘어난다.
- 보호센터 주소 보완. 가려져 있지 않다.
- 원본 주소 가져오기(#172) 방식 변경.

## 작업 순서
각 단계를 PR 하나로 올린다. 1단계 PR은 이 문서다. 승인된 뒤에 2단계부터 코드를 쓴다.

1. 계획 문서 — 문서만
   - 파일: `docs/map/place-address.md`, `docs/map/README.md`, `docs/map/animal-places.md`(S17 주소 줄에 `(고침 #239)`)
   - 확인: `git diff --check`
2. 조회 API — S2, S3, S6, S7, S9 (서버)
   - 파일: 장소 주소 조회 입력 포트와 서비스(`map/application`), 장소를 id로 읽는 저장소 메서드, 건물 이름 처리와 `*` 판정(`map/domain`), `MapController`의 `GET /maps/places/{placeId}/address`, 도로명만 돌려주는 좌표→주소 출력 포트(`LoadRoadAddressPort`)와 `NaverAddressAdapter`의 해당 메서드. 기존 `LoadAddressPort`(#19의 지번 폴백 포함)는 바꾸지 않는다. 키·시간 제한은 #19와 같은 설정을 쓴다.
   - 확인: `./gradlew test --tests '*PlaceAddress*'`. 네이버 응답은 가짜 서버로 흉내 낸다(S9: 도로명 없이 지번만 있는 응답 포함). #19의 주소 조회 테스트(지번 폴백)가 그대로 통과해야 한다. 실제 네이버 호출은 개발 서버에서 한 번 확인한다([직접]).
3. 카드에 찾은 주소 보이기와 복사 — S1, S4, S5, S8, S10 (화면)
   - 시작 조건: 2단계가 개발 서버에 올라간 뒤.
   - 파일: `frontend/features/map/api/placeApi.ts`(주소 조회), `utils/placeAddress.ts`(`*` 판정), `components/PlacesScreen.tsx`(카드의 주소·복사), 이 화면에서 찾은 주소를 장소 id별로 기억하는 작은 훅
   - 확인: `npm test`(S10: A→B 전환 뒤 늦게 온 A 응답 포함), `npm run lint`, `npm run build`, 실제 개발 서버에서 `*` 주소 장소 카드와 복사 결과([직접])

## 정한 것
- **카드에서만, 그 한 곳만 조회한다.** 마커 수백 개를 한꺼번에 조회하면 네이버 호출이 크게 늘고, 사용자가 실제로 보는 것은 카드 하나다. (#239)
- **응답은 장소 id에 묶는다.** 카드가 바뀐 뒤 늦게 온 응답이 다른 카드의 주소와 복사 값을 바꾸지 못하게 한다. (#239)
- **서버가 장소 id로 좌표를 읽어 조회한다.** 화면이 좌표를 보내지 않게 해서 아무 좌표나 조회하는 데 쓰이지 않게 하고, Client Secret이 브라우저로 나가지 않게 한다. 로그인한 회원만 부른다. (#239)
- **DB에 저장하지 않는다.** 네이버 약관에서 결과 저장·캐싱 조항을 아직 확인하지 못했다. 확인하기 전에는 보수적으로 저장하지 않는다. (#239)
- **이 이슈는 도로명 주소만 받아들이고, 기존 지번 폴백은 그대로 둔다.** 기존 `NaverAddressAdapter`는 도로명(`roadaddr`)이 없으면 지번(`addr`)을 돌려주고 결과에 주소 종류가 없다. 그대로 쓰면 S1이 약속한 도로명·건물번호 대신 지번이 성공으로 보이고 복사된다. 그래서 `LoadAddressPort`는 바꾸지 않고(#19의 일기 위치는 지번으로 돌아가는 것이 맞다), 도로명만 돌려주는 출력 포트를 따로 둔다. 둘은 같은 네이버 호출과 설정을 쓴다. (#239)
- **실패는 원래 주소로 돌아간다.** 외부 서비스 장애 때문에 카드가 안 열리거나 오류가 보이지 않게 한다. [#19](memory-location.md)에서 주소 조회 실패가 저장 실패가 되지 않게 한 것과 같은 이유다. (#239)

## 정하지 않은 것
- **서버 메모리에 조회 결과를 잠깐 두는가.** 같은 장소를 여러 사람이 열 때 호출을 줄인다. 약관상 괜찮은지 확인한 뒤 정한다. 당장은 두지 않는다. 화면이 한 번 본 주소를 이 화면에서만 기억하는 것(S4)은 이 결정과 별개다.
- **네이버 호출량을 어떻게 막는가.** 화면에서 카드 하나만 조회하는 것과 API 자체의 호출량 관리는 별개다. 제안 두 가지: (1) 배포 전에 NCP 콘솔에서 사용량 한도를 무료량 안쪽으로 설정한다, (2) 서버에 회원별 호출 제한을 둘지는 구현 전에 이미 있는 제한 장치가 있는지 보고 정한다. 없으면 이번에는 콘솔 한도로 막고 제한 장치는 따로 이슈로 올린다.
- **찾은 주소임을 알리는 문구.** 좌표에서 가장 가까운 도로 주소를 주므로 옆 건물 번호가 나올 수 있다. 제안: 주소 아래에 작게 "좌표로 찾은 주소예요. 실제와 조금 다를 수 있어요"를 보인다. 디자인과 함께 정한다.

## 가정
- 네이버 Reverse Geocoding 무료 이용량은 **대표 계정 기준 월 3,000,000건**이고 초과분은 건당 0.5원(부가세 별도)이다([요금](https://www.ncloud.com/charge/price/ko)). 무료량은 애플리케이션별로 따로 생기지 않고 **같은 계정에서 합산**한다. 그래서 #19의 일기 위치 주소 조회 호출과 합쳐서 추정한다. 카드를 열 때 `*`가 있는 장소만 한 번씩 조회하므로 지금 규모에서 충분하다(예: 하루 사용자 1,000명이 카드를 20번 열어도 한 달 약 60만 건, #19 호출은 이보다 훨씬 적다고 본다). 이 계정은 대표 계정이다. 구현 뒤 NCP 콘솔의 Usage에서 두 기능의 실제 호출 수를 합쳐서 본다.
- 초당·일 호출 한도는 확인하지 못했다. 한도 오류가 나도 S3대로 원래 주소로 돌아가므로 서비스는 계속 동작한다.
- 좌표는 가져올 때 변환한 값이라 건물 위치에 가깝다. 그래도 도로명 주소는 가까운 도로 기준이라 옆 건물 번호가 나올 수 있다. 써 보고 어긋남이 잦으면 문구를 바꾼다.
- 구현 전에 확인할 것: 요청 로그(nginx 등)에 장소 id가 남는 것은 좌표가 아니라 문제가 없지만, 네이버로 나가는 요청이 로그에 남지 않는지 확인한다.

## 참고
- 좌표→주소: `map/adapter/out/geocoding/NaverAddressAdapter`(`LoadAddressPort`). 도로명 주소(`roadaddr`)를 먼저 찾고 없으면 지번 주소로 돌아간다. 키가 없거나 실패하면 빈 값을 돌려준다.
- 원본이 가린 주소의 예: [#172-S17](animal-places.md)의 카드 주소 줄. 이 이슈가 그 동작을 바꾼다.
- 네이버 Reverse Geocoding 요금: 대표 계정 월 3,000,000건까지 무료, 초과분은 건당 0.5원(부가세 별도). [요금](https://www.ncloud.com/charge/price/ko) · [이용량 한도 FAQ](https://www.ncloud.com/support/faq/prod/2828). 서비스 약관의 결과 저장 조항은 이 문서를 쓸 때 직접 확인하지 못했다.
