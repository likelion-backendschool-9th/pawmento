# 정보 지도: 동물병원·동물미용·동물보호센터

관련 이슈: [#172](https://github.com/likelion-backendschool-9th/pawmento/issues/172)

## 한눈에
- 끝나면: 보호자가 정보 지도에서 지도 화면 안의 동물병원·동물미용·동물보호센터를 핀으로 보고, 핀을 누르면 이름·주소·전화(걸 수 있을 때)·24시 여부를 카드로 본다.
- 결정 필요: 없음. 로그인한 회원만 쓰고(#174 리뷰), 출처는 기관명만 먼저 표시한다. 이용 조건은 병원·미용·보호센터 세 API 모두 제한 없음으로 확인했고([가정](#가정)), 세부 문구는 구현 전에 정한다. (고침 #172: 이용 조건을 확인함)
- 규모: 5단계(PR 5개 안팎으로 나눈다)

## 1. 인허가 API로 병원·미용 장소 만들기 (#172-R1)
행정안전부 인허가 API(병원 `animal_hospitals`, 미용 `pet_grooming`)에서 전체를 받아, 영업 중이고 좌표가 올바른 곳만 장소로 저장한다. 같은 관리번호는 갱신하고, 이번 목록에 없는 같은 종류의 장소는 지운다. 단, 이번 수집이 **신뢰할 수 있는 전체 스냅샷**(상태·좌표로 거르기 전의 고유 관리번호 수가 `totalCount`와 같고, `totalCount`가 수집하는 동안 바뀌지 않음)일 때만 갱신과 삭제를 한다. 아니면 아무것도 바꾸지 않는다.

#172-S1 정상 [테스트]
- Given 병원 API가 행 3개를 준다: `SALS_STTS_NM`이 영업/정상이고 좌표가 있는 곳, 폐업, 영업/정상이지만 좌표가 비어 있는 곳
- When  가져오기를 실행한다
- Then  장소 1개가 `HOSPITAL`로 저장된다
- Then  결과로 읽은 행 3, 저장 1, 제외 2(폐업 1, 좌표 없음 1)를 받는다

#172-S2 좌표 변환 [테스트]
- Given 대학로동물병원의 인허가 좌표 X=199947.178659, Y=453593.826987(Bessel 중부원점 TM, EPSG:5174)
- When  위도·경도로 바꾼다
- Then  위도 37.584648, 경도 127.000190에서 5m 이내다. 도쿄 측지계 보정을 하지 않은 값(37.58185, 127.00229)이 아니다
- Then  서울·부산·제주·강원의 기준점 하나씩도 같은 방법으로 5m 이내다

#172-S3 범위 밖 좌표 [테스트]
- Given 영업/정상이지만 `CRD_INFO_X`·`CRD_INFO_Y`가 X=-327.2, Y=-30310.5이거나 변환한 위도·경도가 대한민국 범위(위도 33~39, 경도 124~132) 밖인 행
- When  가져오기를 실행한다
- Then  그 행은 저장하지 않고 제외 건수에 센다. 좌표를 임의로 고치지 않는다
- Then  범위 검사는 위도 33~39, 경도 124~132 상자에서 제주 서남쪽 바다 구석(위도 33.9 미만이면서 경도 126.0 미만)을 뺀 것이다. `X=-327.2, Y=-30310.5`는 변환하면 위도 33.20, 경도 124.85로 상자 안이라서, 이 구석을 빼야 제외된다. 위도 33.9와 경도 126.0의 경계값은 한국으로 보고, 제주 서쪽 끝(33.41, 126.14)·마라도(33.11, 126.27)·가거도(34.07, 125.12)·백령도(37.96, 124.70)·독도(37.24, 131.87)는 제외되지 않는다 (고침 #172: 계획의 예시 좌표가 상자 안으로 변환되어 상자만으로는 제외되지 않았다. #188 리뷰)

#172-S4 다시 가져오기 [테스트]
- Given 관리번호 `300000001019950002`(`MNG_NO`)의 병원이 이미 저장돼 있다
- When  같은 관리번호의 이름·전화가 바뀐 응답으로 다시 가져온다
- Then  행이 늘지 않고 그 행의 이름·전화만 바뀐다
- Given 저장된 병원 중 이번 응답에 없거나 영업 상태가 영업/정상이 아닌 것이 있다(폐업해서 빠진 곳)
- Then  이번 수집이 신뢰할 수 있는 전체 스냅샷이면 그 병원은 지운다. 같은 종류(`HOSPITAL`)만 지우고 다른 종류는 건드리지 않는다. 스냅샷이 신뢰할 수 없으면 누락만으로 지우지 않는다(#172-S5)

#172-S5 불완전한 가져오기 막기 [테스트]
- Given 병원이 5,000건 저장돼 있다
- When  다음 중 하나가 일어난다: 상태·좌표로 거르기 **전**의 고유 `MNG_NO` 수가 `totalCount`와 다르다(페이지 중복으로 다른 관리번호가 빠진 경우 포함), 수집하는 동안 `totalCount`가 바뀐다, 필수 항목(`MNG_NO`, `SALS_STTS_NM`, `CRD_INFO_X`, `CRD_INFO_Y`, `BPLC_NM`)이 빠졌다, 거른 뒤 저장할 건수가 기존의 절반 미만이다, 중간 페이지 호출이 실패하거나 시간 초과한다
- Then  가져오기는 실패로 끝나고 갱신과 삭제가 **하나도** 적용되지 않는다(한 트랜잭션에서 반영한다). 불완전한 수집이 지도를 비우거나 일부만 바꾸지 못하게 하기 위해서다. 다음 실행(수동 포함)에서 처음부터 다시 받는다
- Then  인증키와 요청 주소는 로그나 응답에 남기지 않는다

#172-S20 페이지 나누어 받기 [테스트]
- Given API가 한 번에 최대 100건만 주고 `totalCount`가 250이다
- When  가져오기를 실행한다
- Then  `pageNo`를 1, 2, 3으로 올려 가며 3번 호출한다. 정렬이 보장되지 않아 같은 행이 두 페이지에 오면 관리번호로 하나로 합친다. 합친 뒤 고유 관리번호가 250개일 때만 반영한다
- Given 페이지가 겹쳐 원시 건수는 250이지만 고유 관리번호가 240개다(10개가 빠짐)
- Then  실패로 끝나고 저장된 장소는 하나도 바뀌지 않는다. 빠진 10개를 폐업으로 보고 지우지 않는다(#172-S5)
- Then  호출 사이에 간격을 두고, 하루 호출 한도(개발계정 10,000건)를 넘기지 않는다. 병원 전체는 107번, 미용은 164번이다

미용은 같은 응답 형식(`DTL_TASK_SE_NM`이 더해짐)이고 `GROOMING`으로 저장한다. 위 시나리오를 병원 기준으로 쓰고, 종류별 확인은 [테스트] 하나(#172-S1 미용 버전)로 가리킨다.

## 2. 전화번호와 24시 (#172-R2)
전화는 걸 수 있는 번호만 걸 수 있게 하고, 24시간 영업은 구분해서 보여 준다.

#172-S6 전화번호 정리 [테스트]
- Given 파일의 전화번호가 `0222733233`(10자리), `027339006`(9자리), 주소가 서울특별시인 `36728441`(8자리), 주소가 경기도인 `36728441`(8자리), 빈 값이다
- When  장소로 저장한다
- Then  `02-2273-3233`, `02-733-9006`, `02-3672-8441`, 걸 수 없는 번호, 없음으로 저장된다. 하이픈은 저장할 때 붙인다
- Then  8자리는 서울 주소일 때만 앞에 02를 붙인다. 그 밖의 8자리와 `0`으로 시작하지 않는 번호는 지역번호를 알 수 없어 걸 수 있는 번호로 저장하지 않는다

#172-S7 24시 구분 [테스트]
- Given 병원 이름이 `24시 ○○동물병원`이거나 `진월24동물병원`이고, 보호센터의 운영 시간이 `00:00`~`24:00`이다
- When  저장한다
- Then  이름에 `24시`가 들어 있는 병원은 `open24h=true`, `open24hBasis=NAME`(이름 기반 추정)으로, 운영 시간이 `00:00`~`24:00`인 센터는 `open24h=true`, `open24hBasis=HOURS`(제공된 운영 시간)로 저장된다. `진월24동물병원`은 `open24h=false`다
- Then  이름 기반 값은 검증된 영업시간이 아니다. 화면과 응답은 `NAME`과 `HOURS`를 구분해서 보여 준다(#172-S17)

## 3. 보호센터 가져오기 (#172-R3)
농림축산식품부 보호센터 조회서비스에서 센터를 받아 `SHELTER`로 저장한다. 센터마다 있는 항목이 달라서 없는 값이 있어도 저장한다.

#172-S8 정상 [테스트]
- Given 서비스가 센터 3곳을 준다: 운영 시간과 휴무일(`closeDay`)이 모두 있는 곳, 운영 시간만 있고 `closeDay`가 없는 곳, 위도·경도가 비어 있는 곳
- When  가져온다
- Then  위도·경도가 있는 2곳이 `careRegNo`를 키로 저장된다. 비어 있는 곳은 제외 건수에 센다
- Then  `closeDay`가 없거나 비어 있으면 `closedDays`는 `null`(정보 없음)로 저장한다. 값이 구분자 `+`로 이은 허용 글자(`월요일`~`일요일`, `공휴일`, `연중무휴`)로만 되어 있으면 원본 그대로 저장한다(예: `토요일+일요일`, `일요일+공휴일`). `연중무휴`는 단독일 때만 받는다. 그 밖의 값은 의미를 알 수 없어 "휴무 없음"으로 풀지 않고 `null`로 저장한다(`0`, `1`, `2`, `1+15+10` 같은 숫자 값, `월`처럼 줄인 요일, `격주 토요일`·`명절` 같은 설명, `연중무휴+일요일`처럼 서로 맞지 않는 조합). 원본이 직접 적은 `연중무휴`는 확인된 근거라 그대로 저장한다 (고침 #172: 실제 센터 339곳의 값 분포를 확인하고 저장 규칙을 정함)

#172-S9 서비스 실패 [테스트]
- Given 센터 336곳이 저장돼 있다(실제 센터 339곳 중 위도·경도가 없는 2곳과 범위 밖 1곳은 저장하지 않는다)
- When  서비스가 오류나 시간 초과, 빈 응답을 준다
- Then  저장된 센터는 그대로 남고 가져오기는 실패로 끝난다. 인증키와 요청 주소는 로그나 응답에 남기지 않는다
- Given 서비스가 `totalCount`로 868을 알려 주지만 실제로 있는 센터는 339곳이다(`numOfRows`를 500, 1000으로 해도 339건이 온다)
- Then  보호센터는 `totalCount`로 온전함을 판단하지 않는다. 한 번에 충분히 크게(`numOfRows=500`) 요청해 받은 건수가 요청한 수보다 적으면 끝까지 받은 것으로 본다. 요청한 수와 같거나 많으면 뒤에 더 있을 수 있어 실패로 보고 다음 페이지를 이어 받지 않는다(센터가 500곳에 가까워지면 그때 페이지로 받도록 바꾼다). `careRegNo`가 중복 없이 고유하고 필수 항목이 있으며 저장할 건수가 기존의 **90% 이상**일 때만 반영한다. 받은 건수가 0이면 실패다 (고침 #172: 병원·미용의 "`totalCount`와 같아야 한다"(#172-S5)를 보호센터에 그대로 쓰면 항상 실패해서 보호센터만 다르게 정하고, 그 대신 일부만 받은 응답으로 센터를 대량 삭제하지 못하게 기준을 병원·미용의 절반보다 좁힘. #193 리뷰)
- Given 센터 336곳이 저장돼 있다
- When  서비스가 200건만 주거나(일부만 받음) 302건을 준다
- Then  둘 다 실패로 끝나고 저장된 센터 336곳은 그대로다. 303건(90% 경계)은 반영한다. 병원·미용은 `totalCount`와 고유 수가 같은지를 따로 보므로 기존의 절반 기준을 그대로 쓴다

## 4. 영역 조회 (#172-R4)
지도 화면 영역 안의 장소를 종류별로 조회한다. 반려동물(`petId`)에 의존하지 않고 로그인한 회원이면 누구나 쓴다. 핀 조회와 같이 한 번에 최대 500개를 주고, 넘으면 잘렸다고 알린다. 적용 순서는 영역 → 요청한 종류 → 겹침 제거(요청한 종류 안에서만) → 영역 가운데에 가까운 순 정렬 → 500개 제한이다.

#172-S10 영역 안의 장소 [테스트]
- Given 병원 3곳이 영역 안에, 1곳이 영역 밖에 있다
- When  `GET /maps/places`에 영역(`minLatitude`, `minLongitude`, `maxLatitude`, `maxLongitude`)을 보낸다
- Then  200과 영역 안의 3곳을 받는다. 각 장소는 `id`, `category`, `name`, `address`, `phone`, `latitude`, `longitude`, `open24h`, `open24hBasis`, `openingHours`, `closedDays`(`null`은 정보 없음)를 가진다
- Then  `truncated=false`다

#172-S11 종류 거르기 [테스트]
- Given 영역 안에 병원 2곳, 미용 3곳, 보호센터 1곳이 있다
- When  `categories=HOSPITAL,SHELTER`를 함께 보낸다
- Then  병원 2곳과 보호센터 1곳만 받는다. `categories`를 보내지 않으면 세 종류를 모두 받는다

#172-S12 500개 넘음 [테스트]
- Given 영역 안에 장소가 501개 있다
- When  조회한다
- Then  500개와 `truncated=true`를 받는다. 영역 가운데에 가까운 것부터 500개를 준다. `truncated`는 겹침 제거 **뒤** 개수가 500을 넘을 때만 `true`다(#172-S15)

#172-S13 잘못된 요청 [테스트]
- When  `minLatitude`가 `maxLatitude`보다 크거나, 위도가 91이거나, `categories`에 `CAFE` 같은 없는 종류가 있거나, 영역을 하나라도 빼고 보낸다
- Then  400과 이유를 받는다

#172-S14 로그인 없음 [테스트]
- Given 로그인하지 않았다
- When  `GET /maps/places`를 부른다
- Then  401을 받는다. 정보 지도는 로그인한 회원만 쓴다(#174 리뷰에서 정함)

## 5. 병원과 미용이 겹칠 때 (#172-R5)
같은 곳이 병원과 미용 데이터에 모두 있고 **둘 다 요청했으면** 병원 하나만 보여 준다. 겹침은 요청한 종류 안에서만 따지고, 저장된 데이터는 지우지 않는다.

#172-S15 겹침 제거 [테스트]
- Given 병원 `북악동물병원`과 같은 이름의 미용 장소가 30m 안에 있다(두 데이터 모두에 있는 곳). 이름은 띄어쓰기·괄호·구두점·대소문자를 무시하고 비교한다(`스테이동물병원`과 `스테이 동물병원`은 같은 이름) (고침 #172: 진짜 데이터에서 같은 가게가 띄어쓰기만 다르게 등록된 경우가 253곳 더 있었다)
- When  `categories=HOSPITAL,GROOMING`으로 조회한다
- Then  병원 하나만 나온다. 이름이 같아도 30m보다 멀면 둘 다 나온다
- When  `categories=GROOMING`만 보낸다
- Then  그 미용 장소가 그대로 나온다. 병원이 요청에 없으므로 겹친다는 이유로 빼지 않는다
- Given 겹치는 병원이 영역 밖에 있고 미용 장소만 영역 안에 있다
- Then  영역 안의 후보끼리만 겹침을 판단하므로 미용 장소가 나온다

## 7. 수동 수집 (#172-R7)
관리자는 가져오기를 수동으로 실행할 수 있다. 일반 조회와 별개 컨트롤러이고 `/admin/**` 보호를 따른다.

#172-S22 관리자 수동 실행과 자동 실행 [테스트]
- Given 로그인하지 않았거나 일반 회원이다
- When  `POST /api/v1/admin/places/sync`를 `category=HOSPITAL`로 부른다
- Then  로그인하지 않았으면 401, 일반 회원이면 403이고 수집은 시작되지 않는다. 토큰에 ADMIN이 적혀 있어도 지금 DB의 역할이 관리자가 아니면 403이다
- Given 현재 관리자 역할 검사를 통과한 관리자다(#163과 같은 검사)
- When  같은 요청을 보낸다
- Then  바로 202와 `RUNNING` 상태를 받고, 가져오기는 전용 스레드에서 따로 돈다. 몇 분(병원 약 4분, 미용 약 7분) 걸려서 요청 안에서 기다리면 배포 nginx의 시간 제한(기본 60초)에 걸려 결과를 받을 수 없기 때문이다 (고침 #172: 승인된 계획은 요청 안에서 끝까지 기다려 200과 건수를 돌려줬지만, 배포 경로의 nginx가 60초에 끊어 결과를 받을 수 없어 접수와 조회로 나눔)
- When  `GET /api/v1/admin/places/sync?category=HOSPITAL`로 조회한다
- Then  마지막 가져오기의 상태(`NONE`, `RUNNING`, `SUCCEEDED`, `FAILED`)를 받는다. 성공이면 읽은·저장·제외·추가·갱신·삭제 건수가 있고, 실패(#172-S5)이면 이유(`FETCH_FAILED`, `FETCH_REJECTED`, `LOCK_LOST`, `ALREADY_RUNNING` 등)가 있으며 저장된 장소는 그대로다. 이 서버에서 돌린 적이 없으면 `NONE`이다. 상태는 서버 메모리에만 있어 재시작하면 `NONE`으로 돌아가고, 서버가 여러 대면 대수마다 따로 가진다
- Then  `category`가 없거나 중복이거나 `HOSPITAL`, `GROOMING`이 아니면 400이고 가져오기는 시작되지 않는다 (고침 #172: 계획에서는 `SHELTER`도 받았지만 보호센터는 다른 API라 가져오기를 만들 때 연다)
- Given 같은 종류를 이미 가져오는 중이다
- When  같은 종류를 다시 시작한다
- Then  409이고 받기를 시작하지 않는다. 다른 종류는 막지 않고, 끝나면 다시 가져올 수 있다. 다른 곳(자동 실행 등)이 이미 잠금을 쥐고 있으면 받지 않고 `FAILED(ALREADY_RUNNING)`이다
- Given 가져오는 사이에 잠금을 쥔 DB 연결이 끊겨 잠금을 잃었다
- When  저장하기 직전이 된다
- Then  저장하지 않고 `FAILED(LOCK_LOST)`이다. 다른 실행이 같이 돌았을 수 있어 저장된 장소는 바꾸지 않는다. 잠금을 놓다가 실패한 연결은 풀에 돌려주지 않고 닫아서 서버가 잠금을 풀게 한다
- Given 인증키가 있고 자동 실행이 켜져 있다
- When  매일 한국 시간 새벽 4시 30분이 된다
- Then  앱의 공용 스케줄러가 아닌 별도 스레드에서 병원과 미용을 차례로 가져오고, 한 종류가 실패해도 다른 종류는 이어서 가져온다. 일시 장애는 30분 간격으로 3번까지 다시 시도한 뒤 포기한다(다음 주기에 다시 돈다). 인증 거절·필수 항목 누락처럼 다시 시도해도 같은 실패는 다시 시도하지 않고 멈춘다. 이미 돌고 있으면 건너뛴다
- Then  가져오기는 바깥 트랜잭션 안에서 부를 수 없다(잠금은 DB 연결 하나에 걸려서 트랜잭션보다 수명이 짧아지면 안 된다)

## 정한 것
- 데이터는 공공데이터를 **우리 DB에 적재**해서 쓴다. 카카오 로컬 API는 결과를 저장할 수 없고 실시간 호출만 되며, 호출 한도와 키 보호용 서버 중계가 필요하다. 공공데이터는 우리가 모양과 검색을 정할 수 있다. (#172)
- 쓰는 데이터: 병원(`1741000/animal_hospitals`)과 미용(`1741000/pet_grooming`)은 행정안전부 인허가 조회 API, 보호센터는 농림축산식품부 동물보호센터 조회서비스(API). 모두 서버가 API를 불러 우리 DB에 쌓고, 사람이 파일을 올리지 않는다. 인허가 API는 인허가 파일(CSV)과 같은 원천 데이터이고(받은 병원 100건·미용 100건이 CSV와 이름·상태·좌표까지 같음) 더 최신이다. 파일 다운로드는 첫 적재가 막힐 때의 예비로만 둔다. 병원 5,502건 중 좌표가 올바른 5,268건, 미용 11,376건 중 10,891건, 센터 339곳을 확인했다(API가 알려 주는 `totalCount`는 868이지만 실제로 받을 수 있는 센터는 339곳이다). (고침 #172: 센터는 `totalCount`를 실제 건수로 착각했고, 미용 10,739건은 제주 145곳 등을 잘못 버리는 거친 좌표 범위 검사 때문이라 올바른 검사로 10,891건이다. 2026-11-23 실제 호출로 확인)
- 인허가 좌표(EPSG:5174, Bessel 중부원점 TM)는 **도쿄 측지계 → WGS84 보정을 적용해** 바꾼다. 보정을 빼면 약 375m 어긋난다. 네이버 지도로 대학로동물병원을 확인해 보정한 값이 맞음을 확인했다. (#172)
- 인허가 데이터는 **관리번호(`MNG_NO`)**(18자리 숫자 문자열, 병원·미용 모두 중복 없음)를 키로 갱신한다. 숫자로 읽으면 값이 깨지니 문자열로 읽는다. 보호센터는 `careRegNo`를 키로 한다. (#172)
- 하나의 `places` 테이블에 종류(`category`)로 구분한다. 종류를 더해도 테이블을 만들지 않게 하기 위해서다. API는 한 번에 100건만 주고 정렬이 보장되지 않으며 날짜 조건(`cond[…]`)이 기대대로 거르지 않아, 전체를 받아서 관리번호로 갱신하고 이번에 없는 같은 종류의 장소는 지운다. 고유 관리번호 수가 `totalCount`와 다르거나 기존의 절반보다 적으면 가져오기를 막고, 막힌 수집은 갱신도 삭제도 하지 않는다. (#172-S4, S5, S20)
- 영역 조회는 핀 조회(`GET /maps/pins`)와 같은 모양(최대 500개, `truncated`)으로 만들고, 경로는 `/maps/places`다. 기존 일반 사용자 `MapController`에 메서드로 더하고 반려동물(`petId`)에 의존하지 않는다. 로그인한 회원만 쓴다. (#172, #174 리뷰: 로그인한 회원만)
- 관리자 수동 수집은 `POST /api/v1/admin/places/sync`(202 접수)와 `GET`(상태 조회)이고, `AdminPlaceController`로 분리해 #163의 `/api/v1/admin/**` 보호와 현재 관리자 역할 검사를 따른다. (#172-S22) (고침 #172: 요청 안에서 끝까지 기다리던 동기 실행을 접수(202)와 상태 조회(GET)로 바꿈)
- 24시 배지는 이름 기반이면 "이름 기준 추정"으로 표시하고 운영 시간 기반과 구분한다. 휴무 정보가 없으면 "연중무휴"로 단정하지 않는다. (#174 리뷰)
- 출처는 처음에 기관명("출처: 행정안전부, 농림축산식품부")만 표시한다. 이용 조건은 병원·미용·보호센터 세 API 모두 공공데이터포털의 이용허락범위가 "제한 없음"이다(2026-11-23 활용신청 상세의 라이선스 표시로 확인). 세부 문구는 지도 담당이 구현 전에 확정한다. (#174 리뷰, 고침 #172: 이용 조건을 확인함)
- 미용 파일은 주소의 번지가 `*`로 가려져 있다(영업 중 11,376건 중 11,366건). 좌표는 정상이라 핀은 정확하고, 주소는 가려진 채로 보여 준다. 병원 파일은 가려지지 않았다. (#172)
- 인증키는 환경변수로만 받고, 로그·응답·문서·프론트엔드에 남기지 않는다. 키를 채팅이나 이슈에 붙이지 않고, 노출됐다면 재발급한다. (#172)

## 가정
- 영업 중은 `영업상태명`이 `영업/정상`인 것이다. `휴업`과 `취소/말소/만료/정지/중지`는 제외한다.
- 정렬은 영역 가운데에서 가까운 순이다. 500개를 넘을 때 어느 500개인지 정하기 위해서다.
- 병원과 미용이 겹치는 기준은 이름이 같고 30m 이내다. 실제 데이터로 보고 바꿀 수 있다.
- 전화 걸기는 `0`으로 시작하는 번호와 서울 주소의 8자리 번호(앞에 02)만 허용한다. 전화가 있는 영업 중 병원 3,069건 중 2,954건이 `0`으로 시작하고, 8자리 115건 중 99건이 서울이다. 전화번호 열에는 하이픈이 하나도 없다.
- 장소 응답은 마스킹된 주소를 그대로 준다. 가려진 값을 프론트엔드가 해석하지 않는다.
- 갱신 주기는 인허가(병원·미용)는 하루 1회, 보호센터는 주 1회 자동이다. 병원 107번, 미용 164번 호출은 하루 한도(개발계정 10,000건)에 비해 작다. 운영 계정 신청은 활용 사례가 필요해서 개발계정으로 시작한다.
- 처음 보여 줄 지도 위치는 서울 종로구다. 위치 권한은 이 이슈에서 다루지 않는다("내 위치"는 후속).
- 구현 전에 확인할 것: 인허가 `DAT_UPDT_SE` 값의 의미와 폐업·삭제 행이 이후 페이지에 오는지, 겹침 기준 30m의 실제 데이터 적합성, #168(체험 모드) 결정.

## 참고
- 인허가 API 응답은 열이 25개(미용은 `DTL_TASK_SE_NM`이 더해진 26개)다. 좌표는 `CRD_INFO_X`·`CRD_INFO_Y`(TM 문자열), 키는 `MNG_NO`, 상태는 `SALS_STTS_NM`, 전화는 `TELNO`(대부분 하이픈 포함), 도로명 주소는 `ROAD_NM_ADDR`, 갱신 시각은 `DAT_UPDT_PNT`다. `DAT_UPDT_SE`(I/U 등)의 값 의미는 구현 때 확인한다. 한 번에 최대 100건이며 `numOfRows=1000`을 보내도 100건만 온다. 첫 페이지 100건은 모두 영업/정상이어서 폐업 행이 이후 페이지에 오는지는 구현 때 확인한다. 호출 하나(100건)가 약 0.6초라서(2026-11-23 측정) 병원 107번과 미용 164번을 합쳐 약 3분이다.
- 인허가 파일(CSV)은 [file.localdata.go.kr](https://file.localdata.go.kr)의 "동물_동물병원", "동물_동물미용업"이며 문자 인코딩이 CP949다. API와 같은 데이터라서 예비로만 둔다.
- 인허가 좌표에는 올바르지 않은 값이 있다. 약국 파일 기준 영업 중 13,796건 중 208건이 음수이거나 범위 밖이었다(`X=-327`, `Y=-30310` 같은 값). 병원·미용도 같은 검사를 한다.
- 한국 범위 검사는 실제 국토 경계를 판정하는 것이 아니라 이 데이터셋의 잘못된 좌표를 거르는 거친 유효성 필터다. 바다 위의 올바르지 않은 좌표를 모두 거르지는 못한다. (#188 리뷰)
- 인허가 전화번호는 병원 영업 중의 약 56%, 미용의 약 26%에만 있다. 전화가 없는 장소는 정상이다.
- 병원 이름에 "24"가 든 195곳 중 190곳이 "24시"이고, 나머지 5곳(`진월24동물병원` 등)은 24시간 운영이 아니다. 그래서 "24시"가 든 이름만 24시로 본다.
- 보호센터 API: `https://apis.data.go.kr/1543061/animalShelterSrvc_v2/shelterInfo_v2`. 응답이 JSON이고 `lat`, `lng`이 WGS84로 들어 있어 변환이 없다. 센터마다 있는 항목이 달라 없을 수 있는 값으로 읽는다. `jibunAddr`은 `" 6층"`처럼 온전하지 않은 값이 있어 도로명 주소(`careAddr`)만 쓴다. `orgNm`(관할)은 주소와 다를 수 있어 쓰지 않는다.
- 공공데이터포털 인증키 두 가지(Encoding/Decoding) 중 서버 설정에 넣는 형태에 따라 `+`·`/`가 깨질 수 있다. 호출이 인증 오류를 내면 키 형태부터 확인한다.
- [전국동물병원표준데이터](https://www.data.go.kr/data/15155679/standard.do)는 이 인허가 병원 파일과 같은 데이터다(같은 `file.localdata.go.kr` 파일, 좌표계도 EPSG:5174이고 2025-11-27 기준이라 더 오래됨). 위도·경도 파일이 아니므로 비교 기준이나 변환을 건너뛰는 방법으로 쓸 수 없다.
- 변환 오차는 두 가지로 확인한다. 테스트에 지역별 기준점(서울·부산·제주·강원)을 넣어 5m 이내를 계속 확인하고, 3단계 PR에서 병원 몇 곳을 골라 주소로 네이버 주소 검색(Geocoding)을 해서 좌표를 비교한 결과를 PR 본문에 적는다.
- 동반 장소 후속 조사: 한국관광공사 `KorPetTourService2`는 목록(`areaBasedList2`, 좌표·이름·주소, 전화 없음)과 상세(`detailPetTour2`, 동반 조건)가 나뉘어 있어 9,630건이면 상세 호출이 약 9,600번이다. 저장 가능한 이용 조건을 확인하기 전에는 가져오지 않는다.
- 인허가 API(`/info`)의 데이터는 매일 갱신되고 2일 전 기준으로 현행화된다. 같은 서비스의 `/history`(이력조회)는 기준일자(2026-01-01부터)를 넣어 그 시점의 데이터를 조회할 수 있지만, 지금은 전체를 받아 갱신하므로 쓰지 않는다. 상세기능마다 개발계정 일일 트래픽이 10,000건이다. (2026-11-23 활용신청 상세에서 확인)
- 보호센터 API는 `numOfRows`를 500이나 1000으로 해도 339건만 주고 페이지 4(100건씩)에서 끝나며, 중복 없이 `careRegNo`가 고유하다. 호출은 평균 0.24초이고 오류가 없었다. 값 분포(2026-11-23, 339곳): `closeDay`는 요일·공휴일 글자가 대부분(`토요일+일요일` 85, `일요일` 79, `일요일+공휴일` 40 등), `연중무휴` 9, 숫자 값 `0` 50·`1` 3·`2` 1·`1+15+10` 1, 항목 없음 2다. 24시간(`00:00`~`24:00`) 운영 25곳, 운영 시간 없음 2곳, 위도·경도 없음 2곳과 범위 밖 1곳, 전화 없음 0곳이다. 데이터 기준 일자(`dataStdDt`)는 가장 오래된 것이 2022-01-14라서, 화면의 "데이터 기준"(#172-S21)을 정할 때 센터 정보가 오래된 곳이 있음을 고려한다.
