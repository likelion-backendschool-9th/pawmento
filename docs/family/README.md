# family

한 반려동물을 소유주와 가족이 함께 기록하는 기능이다. 가족은 소유주나 다른 가족이 만든 초대 코드로 들어온다. 가족 멤버십과 "이 회원이 이 반려동물의 소유주인가, 가족인가"를 확인하는 입력 포트는 이 도메인이 맡고, 다른 도메인(diary, question, media 등)은 이 포트로 접근을 확인한다.

## 역할과 권한

역할은 소유주(`OWNER`)와 가족(`FAMILY`) 둘뿐이다. (#133)

| 동작 | 소유주 | 가족 | 관계없는 회원 |
| --- | --- | --- | --- |
| 다이어리·질문 답변 보기·쓰기 | O | O | X |
| 본인 다이어리·답변 수정·삭제 | O | O | - |
| 다른 사람 다이어리·답변 삭제 | O | X | X |
| 다른 사람 다이어리·답변 수정 | X | X | X |
| 반려동물 정보 수정·모드 변경 | O | X | X |
| 반려동물 삭제 (가족이 있으면 가장 먼저 가족이 된 회원이 이어받음) | O | X | X |
| 초대 코드 만들기 | O | O | X |
| 다른 가족 내보내기 | O | X | X |
| 스스로 나가기 | X (먼저 소유주 이전이나 반려동물 삭제) | O | - |
| 소유주 이전 | O | X | X |

## 데이터 구조 요약

`pet_family_members` — 가족 멤버십 (#133)

| 컬럼 | 설명 |
| --- | --- |
| `id` | 멤버십 id |
| `pet_id` | 반려동물 id |
| `member_id` | 가족 회원 id |
| `joined_at` | 가족이 된 시각 |
| 제약 | `(pet_id, member_id)` 유일 |

`pet_invite_codes` — 초대 코드 (#133)

| 컬럼 | 설명 |
| --- | --- |
| `id` | 코드 id |
| `pet_id` | 반려동물 id |
| `code_hash` | 코드 해시(유일). 원문은 저장하지 않는다 |
| `issuer_member_id` | 발급한 회원 id. 이 회원이 나가거나 내보내지면 코드도 지운다 |
| `expires_at` | 만료 시각(발급 후 24시간) |
| `created_at` | 발급 시각 |

소유주는 이 도메인에 저장하지 않고 pet의 `owner_member_id`를 읽는다.

## 정한 것
- 소유주는 pet의 `owner_member_id`에 두고, 가족만 이 도메인에 저장한다. (#133)
- 커뮤니티 글은 가족 권한에 들어가지 않는다. (#133)
- 가족 API는 `/api/v1/families`이고 반려동물은 `petId` 입력으로 받는다. (#133)
- 가족이 있는 반려동물을 소유주가 삭제하면 반려동물은 남고, 가장 먼저 가족이 된 회원이 소유주가 되며 이전 소유주는 나간다. 가족이 없으면 지금처럼 삭제하고 초대 코드도 함께 지운다. (#133)
- 회원 탈퇴: 데이터는 30일 보관 후 영구 삭제하고, 소유주에게는 양도를 안내하며, 양도하지 않으면 가장 먼저 가족이 된 회원이 이어받는다. (팀 합의, 탈퇴 이슈에서 구현)
- 가족 상태를 바꾸는 요청(코드 발급, 가입, 나가기, 내보내기, 이전, 반려동물 삭제)은 모두 반려동물 행을 먼저 잠근다. (#133)

## 아직 정하지 않은 것
- 나간 가족이 쓴 글을 지울지 (지금은 남긴다)
- 회원 탈퇴 때 가족이 없는 반려동물의 데이터 삭제 흐름 (탈퇴 이슈)
- 초대 코드 발급 횟수 제한 (지금은 제한 없음, 만료 코드는 발급 때 정리)
