# 반려동물 출생 연도와 나이

관련 이슈는 [#178](https://github.com/likelion-backendschool-9th/pawmento/issues/178)이다. 기존 등록·관리 계약은 [#46 반려동물 등록·관리](manage.md)를 따른다.

## 한눈에

- 보호자는 월·일을 모르면 출생 연도만 입력한다. 목록·상세에서 출생 정보와 연도 기준 나이를 확인한다.
- 나이는 한국 시간 1월 1일에 한 살 증가한다. 기존 날짜 데이터와 `birthday` 입출력 계약을 유지한다.

## 1. 출생 정보 등록과 나이 조회

- **#178-R1** 정확한 생년월일이 없어도 출생 연도를 등록할 수 있다. 기존 생년월일과 출생 정보가 없는 반려동물도 그대로 조회할 수 있다.
- **#178-R2** 조회할 때 한국 시간의 현재 연도에서 출생 연도를 빼서 연도 기준 나이를 계산한다.

### #178-S1 연도만 등록 [테스트]

- Given 소유자 A가 로그인했고 한국 시간 기준 2026년이다.
- When A가 `birthYear: 2020`과 기존 등록 필수값을 보내고 목록·상세를 다시 조회한다.
- Then 등록은 201이고 목록·상세에 `birthday: null`, `birthYear: 2020`, `ageByYear: 6`을 반환한다. 재조회해도 연도가 유지된다.

### #178-S2 해가 바뀌면 나이 갱신 [테스트]

- Given 한 반려동물은 2020년만, 다른 반려동물은 `birthday: "2020-12-31"`을 저장했다.
- When 고정 시계로 `2026-12-31T14:59:59Z`와 `2026-12-31T15:00:00Z`에 각각 조회한다.
- Then 한국 시간 2027년 1월 1일 자정을 경계로 두 반려동물의 `ageByYear`가 모두 6에서 7로 바뀐다. 저장된 출생 정보와 버전은 바뀌지 않는다.

### #178-S3 기존 등록·저장 데이터 호환 [테스트]

- Given 구형 PostgreSQL 스키마에 `birthday: "2020-05-12"`인 행, `birthday: "1899-12-31"`인 행, 출생 정보가 없는 행이 있다.
- When 새 스키마로 올린 뒤 소유자가 목록·상세를 조회하고 기존 요청 형식으로 정확한 날짜를 포함해 등록·수정한다.
- Then 모든 기존 행의 `birth_year`는 NULL이며, 날짜는 그대로 반환하고 연도와 나이는 날짜에서 계산한다. 출생 정보가 없는 행은 날짜·연도·나이가 모두 `null`이다. 1900년 이전의 날짜를 포함해 날짜만 보내는 기존 등록·수정 방식도 성공한다.
- When 스키마 이관을 다시 실행하고 DB에 날짜와 연도를 함께 쓰려고 한다.
- Then 이관은 기존 데이터를 보존하고, DB는 두 값이 함께 저장되는 INSERT와 UPDATE를 거절한다.

## 2. 출생 정보 수정과 검증 (#178-R3)

소유자는 출생 연도 또는 정확한 날짜를 수정할 수 있다. 수정 화면에 기존 연도가 미리 채워져 있어도 정확한 날짜는 보존한다.

### #178-S4 날짜·연도 전환 및 기존 값 보존 [테스트]

- Given 소유자 A의 반려동물에 `birthday: "2020-05-12"`가 저장돼 있다.
- When A가 이름을 수정하면서 출생 정보로 `birthYear: 2020`만 전송한다.
- Then 이름은 갱신되고 날짜 `"2020-05-12"`와 연도 2020은 유지된다.
- When A가 출생 정보로 `birthYear: 2021`만 전송하거나 `birthday: null`과 `birthYear: 2021`을 함께 전송한다.
- Then 두 요청 모두 정확한 날짜가 해제되고 연도 2021만 저장된다.
- When A가 정확한 날짜를 다시 저장하고, 이후 이름만 수정하거나 `birthday: null`만 전송한다.
- Then 정확한 날짜가 유지된다. 다른 회원의 수정은 기존대로 403이다.

### #178-S5 잘못된 출생 정보 검증 [테스트]

- Given 한국 시간 기준 2026년이며 소유자 A의 반려동물이 있다.
- When A가 등록·수정에서 범위를 벗어난 연도(-1, 0, 1899, 2027), 불리언 `true`, 배열 `[2020]`, 문자열 `"2020"`, 소수 표기 `2020.0`·`2020.5`, 지수 표기 `1e3`, 정수 범위를 넘는 `2147483648`, 존재하지 않는 날짜, 미래 날짜 또는 날짜와 다른 출생 연도를 보낸다.
- Then 공통 400 `VALIDATION`을 반환한다. 실패한 등록은 행을 만들지 않고, 실패한 수정은 기존 출생 정보와 함께 보낸 다른 필드도 보존한다.
- When A가 월·일 없이 `birthYear: 1900` 또는 `birthYear: 2026`만 등록한다.
- Then 두 경계 모두 등록할 수 있고 연도 기준 나이는 각각 126과 0이다.

## API와 저장 계약안

| 경우 | 요청·응답 |
| --- | --- |
| 정확한 일자를 아는 경우 | 기존 등록·수정의 `birthday: "2020-05-12"` 형식과 응답을 유지한다. `birthYear`도 유효한 값으로 함께 보내면 날짜와 같은 연도여야 한다. 저장할 때는 날짜를 기록하고 연도 전용 값은 비운다. |
| 연도만 등록 | `POST /api/v1/pets`에 `birthYear`를 보낸다. `birthday`는 `null`로 반환한다. |
| 연도만 수정 | `PATCH /api/v1/pets/{petId}`에 값이 있는 `birthYear`를 보내고 `birthday`를 생략하거나 `null`로 보내면 아래 규칙을 적용한다. 기존 날짜와 같은 연도이면 출생 정보 변경 없이 날짜를 보존한다. 기존 날짜와 다른 연도이면 날짜를 비우고 새 연도만 저장한다. |
| 출생 정보를 모르는 경우 | 등록에서 두 필드를 생략하거나 `null`로 보내면 출생 정보 없이 등록한다. 수정에서 두 필드 모두 실제 값이 없으면 기존 출생 정보를 유지한다. |
| 조회·변경 응답 | 기존 `birthday`를 유지하고 `birthYear`, `ageByYear`를 추가한다. 날짜가 있으면 응답의 `birthYear`는 날짜에서 구하고, 날짜가 없으면 저장한 `birth_year`를 사용한다. 등록·수정·모드 변경 응답도 같은 형식을 쓴다. 출생 정보가 없으면 세 필드 모두 `null`이다. |

- 값이 있는 `birthYear`는 JSON의 정수 숫자만 허용한다. 등록·수정 요청에서 값 형식과 32비트 정수 범위를 변환 전에 확인하고, 형식·범위 오류는 400 `VALIDATION`으로 처리한다. 생략과 명시적 `null`은 값 없음으로 처리한다.
- `pets.birthday`를 유지하고 nullable `birth_year INTEGER`를 추가한다. 날짜와 연도 전용 값의 동시 저장은 도메인에서 막고, PostgreSQL에도 `CHECK (birthday IS NULL OR birth_year IS NULL)`을 둔다.
- Hibernate가 `birth_year`를 추가한 뒤 pet의 스키마 초기화 트랜잭션에서 명명된 CHECK 제약을 적용한다. 제약이 이미 있으면 건너뛰고, 처음 적용할 때 PostgreSQL이 기존 행까지 검증하도록 한다. 기존 행을 UPDATE하거나 가상의 날짜를 채우지 않는다.
- 소유권과 기존 버전 충돌 정책을 유지한다.

## 범위 밖

- 입력 화면의 월·일 공란과 연도 기준 나이 표시를 위한 프론트 연동.
- 생일의 월·일을 기준으로 하는 만 나이 및 저장된 출생 정보 전체 삭제.

## 정한 것

- 새 `birthYear`의 범위는 1900년부터 한국 시간의 현재 연도까지다. 고정 하한으로 자리수가 빠진 연도 입력을 막으면서 보호자가 알고 있는 과거 연도를 입력할 수 있게 한다. 기존 `birthday`는 오늘·과거를 허용하는 계약을 유지하므로 1900년 이전의 정확한 날짜도 보존한다.
- `ageByYear`는 `Asia/Seoul`의 현재 연도에서 출생 연도를 뺀 값이다. 월·일을 아는지와 관계없이 동일한 표시 기준을 적용하면 이 값은 한 번의 연도 변경으로 함께 갱신된다. 예를 들어 2020-12-31생의 2026-01-01 기준 `ageByYear`는 6이다. 후속 화면에서는 ‘연도 기준 6살’처럼 기준을 함께 표시한다.
- 저장한 출생 정보로부터 기존 `Clock`을 이용해 나이를 계산한다. 목록 한 요청에서는 같은 시점을 사용하고, 조회만으로 나이·출생 정보·버전이 DB에 기록되거나 바뀌지 않는다.
- 월·일을 모르면 연도만 저장한다. 가상의 월·일을 넣으면 소유자가 알려 준 정확한 날짜와 구분할 수 없다.

## 가정

- 이용자가 같은 해의 정확한 생년월일에서 월·일을 지우는 별도 동작은 이번 범위에서 제공하지 않는다. 별도의 삭제 요청 형식이 필요해지면 후속 계약으로 다룬다.
- DB 이관 검사에서는 연도 전용 컬럼이 없는 기존 PostgreSQL 스키마를 준비한다. 기존 행은 새 컬럼의 NULL 기본값으로 호환된다.
