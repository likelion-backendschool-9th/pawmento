# 반려동물 출생 연도와 나이

관련 이슈: [#178](https://github.com/likelion-backendschool-9th/pawmento/issues/178). 기존 등록·관리 계약은 [#46 반려동물 등록·관리](manage.md)를 따른다.

## 한눈에

- 보호자는 월·일을 모르면 출생 연도만 입력한다. 목록·상세에서 출생 정보와 연도 기준 나이를 확인한다.
- 나이는 한국 시간 1월 1일에 한 살 증가한다. 기존 반려동물 데이터와 `birthday` 입출력 계약을 유지한다.
- 작업 순서는 출생 정보 저장 → API와 나이 계산 → 기존 데이터와 오류의 통합 검증이다.

## 1. 출생 연도 등록과 기존 데이터 조회 (#178-R1)

정확한 생년월일이 없어도 출생 연도를 저장할 수 있으며, 기존 날짜 데이터도 그대로 조회할 수 있다.

### #178-S1 연도만 등록 [테스트]

- Given 소유자 A가 로그인했고 한국 시간 기준 2026년이다.
- When A가 `birthYear: 2020`과 기존 등록 필수값을 보내고 목록·상세를 다시 조회한다.
- Then 등록은 201이고 목록·상세에 `birthday: null`, `birthYear: 2020`, `ageByYear: 6`을 반환한다. 재조회해도 연도가 유지된다.

### #178-S3 기존 등록·저장 데이터 호환 [테스트]

- Given 기존 DB에 `birthday: "2020-05-12"`인 행과 출생 정보가 없는 행이 있다.
- When 소유자가 목록·상세를 조회하고, 기존 요청 형식으로 정확한 날짜를 포함해 새 반려동물을 등록한다.
- Then 기존 날짜를 그대로 반환하고 연도와 나이를 계산한다. 출생 정보가 없는 행은 날짜·연도·나이가 모두 `null`이다. 날짜만 보내는 기존 등록 방식도 성공한다.

## 2. 한국 시간 기준 나이 조회 (#178-R2)

나이는 생일의 월·일과 관계없이 한국 시간의 현재 연도에서 출생 연도를 빼서 조회할 때 계산한다.

### #178-S2 해가 바뀌면 나이 갱신 [테스트]

- Given 2020년생 반려동물의 출생 정보가 저장되어 있다.
- When 고정 시계로 `2026-12-31T14:59:59Z`와 `2026-12-31T15:00:00Z`에 각각 조회한다.
- Then 한국 시간 2027년 1월 1일 자정을 경계로 나이가 6에서 7로 바뀐다. 저장된 출생 정보와 버전은 바뀌지 않는다.

## 3. 출생 정보 수정과 검증 (#178-R3)

소유자는 연도만 기록한 상태와 정확한 날짜를 기록한 상태를 서로 전환할 수 있다.

### #178-S4 날짜·연도 전환 및 기존 값 보존 [테스트]

- Given 소유자 A의 반려동물에 `birthday: "2020-05-12"`가 저장돼 있다.
- When A가 `birthYear: 2020`만 전송한다.
- Then 월·일 없이 연도만 조회된다.
- When A가 정확한 날짜를 다시 저장하고, 이후 이름만 수정하거나 `birthday: null`만 전송한다.
- Then 정확한 날짜가 유지된다. 다른 회원의 수정은 기존대로 403이다.

### #178-S5 잘못된 출생 정보 검증 [테스트]

- Given 한국 시간 기준 2026년이며 소유자 A의 반려동물이 있다.
- When A가 미래 연도 2027, 0년, 비정수 연도, 존재하지 않는 날짜, 미래 날짜 또는 날짜와 다른 출생 연도를 보낸다.
- Then 공통 400 `VALIDATION`을 반환하고 기존 출생 정보와 함께 수정한 다른 필드도 변경되지 않는다.
- When A가 월·일 없이 올해인 `birthYear: 2026`만 등록한다.
- Then 등록할 수 있고 연도 기준 나이는 0이다.

## API와 저장 계약안

| 경우 | 요청·응답 |
| --- | --- |
| 정확한 일자를 아는 경우 | 기존 등록·수정의 `birthday: "2020-05-12"` 형식과 응답을 유지한다. `birthYear`를 함께 보냈으면 같은 연도여야 한다. |
| 연도만 아는 경우 | `POST /api/v1/pets` 또는 `PATCH /api/v1/pets/{petId}`에 정수 `birthYear`를 보낸다. `birthday`는 `null`로 반환한다. |
| 출생 정보를 모르는 경우 | 등록할 때 두 필드를 비운다. 기존 반려동물 수정에서 두 필드를 생략하거나 둘 다 값이 `null`이면 기존 출생 정보를 유지한다. |
| 조회·변경 응답 | 기존 pet 응답의 `birthday`를 유지하고 `birthYear`, `ageByYear`를 추가한다. 등록·수정·모드 변경 응답에도 같은 형식을 쓴다. 출생 정보가 없으면 세 필드 모두 `null`이다. |

- 기존 nullable `birthday` 날짜 컬럼을 유지한다. 연도만 아는 경우를 위해 nullable `birth_year` 정수 컬럼을 추가하고, 정확한 날짜와 연도 전용 값 중 하나만 저장한다. 기존 행의 날짜를 변경하거나 가상의 월·일을 채우지 않는다.
- 새 `birthYear`는 1부터 한국 시간의 현재 연도까지 받는다. 정확한 날짜는 기존과 같이 오늘·과거만 허용한다.
- `ageByYear`는 `Asia/Seoul`의 현재 연도에서 출생 연도를 뺀 값이다. 기존 `Clock`을 사용하며 목록 한 요청의 모든 항목은 같은 시점을 기준으로 계산한다. 나이는 DB에 저장하지 않는다.
- 소유권·기존 버전 충돌 정책은 유지한다. 프론트가 입력 UI를 연결할 때 `birthYear`만 보내면 정확한 날짜를 연도 전용 값으로 전환하는 계약을 따른다.

## 작업 순서

1. pet 도메인·저장소에 출생 연도 옵션을 추가한다. 기존 날짜와 미상 레코드의 호환을 확인한다 (#178-S3).
2. 기존 등록·수정 요청과 목록·상세 응답에 출생 연도를 연결한다. 한국 시간 기준 나이 계산과 유효성 검사를 추가한다 (#178-S1, #178-S2, #178-S4, #178-S5).
3. PostgreSQL 통합 테스트에서 기존 데이터 조회, 저장 후 재조회 및 잘못된 입력의 원본 보존을 확인한다.

## 범위 밖

- 입력 화면의 월·일 공란과 연도 기준 나이 표시를 위한 프론트 연동.
- 생일의 월·일을 기준으로 하는 만 나이 및 저장된 출생 정보 전체 삭제.
