# 반려동물 프로필 사진

관련 이슈: [#130](https://github.com/likelion-backendschool-9th/pawmento/issues/130). 기존 반려동물 API와 삭제 정책은 [#46 계획](manage.md), 업로드와 정리는 [미디어 계약](../media/README.md)과 [실행 문서](../media/runtime.md)를 따른다.

## 한눈에

- 끝나면: 소유자가 반려동물마다 사진 한 장을 연결하고 목록·상세에서 보며, 교체·제거하거나 반려동물과 함께 삭제할 수 있다.
- 리뷰가 필요한 범위: pet 연결을 미디어의 실제 사용 여부 검사에 넣는 지점과 `PET_PROFILE`의 업로드·검증·참조·조회 경로를 미디어 담당과 확인한다.
- 규모: 미디어 용도와 참조 검사 연결 → pet 사진 연결·조회 → 교체·삭제와 통합 검사.

## 1. 사진 업로드와 최초 연결 (#130-R1)

소유자는 반려동물을 먼저 등록하고, 검증이 완료된 사진 한 장을 해당 반려동물에 연결할 수 있다.

### #130-S1 등록 후 READY 사진 연결 [테스트]

- Given A가 반려동물 10을 등록했고 목록·상세의 `profilePhoto`는 `null`이다.
- When A가 반려동물 10의 `PET_PROFILE` 이미지 101을 업로드하고 상태가 `READY`가 된 뒤 연결한다.
- Then 연결 요청은 200이고 목록·상세에 사진 ID 101과 인증된 파일·썸네일 경로가 표시된다.
- Then 반려동물 10의 사진 연결은 하나, 사진 101의 참조 수는 1이다. 같은 사진을 다시 연결해도 참조 수는 1이다.

### #130-S2 동기 입력 오류와 비동기 검증 오류 [테스트]

- Given A의 반려동물 10이 등록되어 있다.
- When `PET_PROFILE`에 음성 또는 지원하지 않는 형식을 보내거나, 15MiB를 1바이트 넘기거나, 크기 필드·multipart 형식이 잘못된 요청을 보낸다.
- Then 각각 기존 미디어 계약에 따라 415·413·400을 반환한다. 정확히 15MiB인 유효한 이미지는 용량 기준을 통과한다.
- When 수신은 됐지만 이미지 파싱 또는 4천만 픽셀 제한을 비동기 검사에서 통과하지 못한다.
- Then 상태 조회는 `REJECTED`를 반환한다. 반려동물은 남고 사진은 연결되지 않아 다시 업로드할 수 있다. (고침 #130: 이슈의 일괄 400을 미디어 오류 계약으로 구분)

### #130-S3 다른 용도·반려동물·업로더 또는 아직 연결할 수 없는 사진 [테스트]

- Given A가 반려동물 10과 20을 소유하고, 반려동물 10에는 기존 사진 101이 연결돼 있다.
- When A가 반려동물 20의 사진, 다른 회원의 자산 또는 일기용 자산을 반려동물 10에 연결한다.
- Then 기존 media 참조 검사와 같은 404를 반환한다.
- When A가 소유·대상·용도가 맞는 `PROCESSING`, `REJECTED` 또는 연결 유효기간이 지난 사진을 연결한다.
- Then 409를 반환한다. 사진 101의 연결과 참조 수는 유지되고 삭제 작업은 등록되지 않는다.

## 2. 사진 조회와 권한 (#130-R2)

목록·상세는 사진 유무를 표시하고, 파일과 썸네일은 소유자가 현재 연결된 사진을 요청한 경우에만 제공한다.

### #130-S4 표시와 파일 접근 [테스트]

- Given A의 반려동물 10에는 사진 101이 있고, 반려동물 20에는 사진이 없다.
- When A가 자기 목록·상세와 사진 101의 파일·썸네일을 조회한다.
- Then 10은 `profilePhoto.assetId=101`과 인증된 경로를, 20은 `profilePhoto=null`을 반환한다.
- Then 파일 요청은 올바른 MIME으로 가공된 서비스본 또는 썸네일을 반환하고, 서비스본에는 EXIF가 없으며 GPS 후보가 생성되지 않는다.
- When 로그인하지 않은 요청이나 B가 10의 파일·썸네일을 읽거나 사진을 업로드·교체·제거한다.
- Then 비로그인은 401, 다른 회원 B는 403이며 파일 바이트와 사진 정보가 노출되지 않고 연결도 바뀌지 않는다.

### #130-S5 연결 전과 이전 사진의 접근 [테스트]

- Given 사진 101은 A가 업로드한 READY 사진이고, 이후 A가 101을 연결했다가 102로 교체한다.
- When 연결 전 A와 B가 기존 media preview를 요청하고, 교체 후 A가 pet 경로에서 이전 사진 101을 조회한다.
- Then 연결 전 preview는 업로더 A만 접근할 수 있다.
- Then 교체 후 pet 경로에서 101은 404이고 102만 조회된다. 102 제거 후에도 같은 보호가 적용된다.

## 3. 사진 교체·제거와 반려동물 삭제 (#130-R3)

사진 연결·참조 수·정리 작업을 같은 트랜잭션에서 갱신하고, 교체나 삭제가 실패하면 기존 상태를 보존한다.

### #130-S6 교체·제거와 참조 정리 [테스트]

- Given 반려동물 10의 사진 101은 참조 수가 1이고 새 사진 102는 연결 가능한 READY 상태다.
- When A가 102로 교체한다.
- Then pet은 102만 가리키고 참조 수가 1이 된다. 101은 참조가 0이고 실제 연결도 없으면 한 번만 정리에 등록된다.
- When A가 102를 제거하고 같은 제거 요청을 다시 보낸다.
- Then 두 요청은 204이고 `profilePhoto=null`이다. 참조 수를 두 번 줄이거나 정리를 중복 등록하지 않는다.

### #130-S7 동시 변경과 실패 복구 [테스트]

- Given 별도 PostgreSQL 트랜잭션에서 A의 두 변경 요청이 같은 기존 반려동물 버전과 사진 101을 읽는다.
- When 한쪽 요청이 사진을 교체하고 커밋한 뒤 다른 쪽이 이전 버전으로 교체 또는 제거를 시도한다.
- Then 늦은 요청은 409이고 먼저 저장된 사진·참조 수·정리 내역을 보존한다.
- When 별도 검사에서 pet 연결을 바꾼 뒤 미디어 참조 변경이나 반려동물 삭제가 실패한다.
- Then 새 트랜잭션으로 확인했을 때 연결·참조 수·삭제 작업 등록이 모두 변경 전 상태다.

### #130-S8 직접 삭제·정리 작업으로부터 활성 사진 보호 [테스트]

- Given 반려동물 10이 사진 101을 참조하지만 사진의 `reference_count`가 잘못 0으로 저장됐다.
- When 소유자가 media 직접 삭제를 요청하거나 정리 작업이 사진 101을 확인한다.
- Then 직접 삭제는 409이고 정리 작업은 사진 101을 삭제 대상으로 등록하지 않는다. pet 사진을 계속 조회할 수 있다.

### #130-S9 반려동물 삭제와 기존 기록 제한 [테스트]

- Given 반려동물 10에는 사진만 있고, 20에는 사진과 삭제를 막는 기존 연관 기록이 있다.
- When A가 10과 20을 각각 삭제한다.
- Then 10은 204이고 사진 연결 해제·참조 수 감소·마지막 참조 정리 작업 등록이 함께 커밋된다. 파일 제거는 기존 작업자가 수행한다.
- Then 20은 기존 409를 반환하고 반려동물·사진·참조 수·정리 상태가 유지된다. 일기·질문 답변·엽서가 각각 삭제를 차단하는 기존 계약을 보존한다.

## API와 데이터 계약안

아래 경로는 `/api/v1` 기준이다. 웹·백엔드가 사용할 경로와 응답 이름은 이 계획에서 정하고, 기존 필드는 제자리에서 유지한다.

| 요청 | 입력과 응답 |
| --- | --- |
| 기존 `POST /pets` | 기본 정보로 201. 사진 없이 등록한 뒤 받은 `petId`로 미디어 세션을 연다. |
| 기존 `POST /media/uploads?petId={petId}`, `POST /media/{assetId}/content?petId={petId}`, `GET /media/{assetId}?petId={petId}` | `purpose=PET_PROFILE`로 세션을 만들고 기존 multipart 업로드·상태 조회를 사용한다. 프로필 사진에 위치 동의는 적용하지 않는다. |
| `PUT /pets/{petId}/profile-photo` | 양의 정수 `assetId`를 JSON으로 받아 연결 또는 교체한다. 200과 갱신된 반려동물 정보를 반환한다. |
| `DELETE /pets/{petId}/profile-photo` | 현재 연결을 해제하고 204를 반환한다. 소유자에게 이미 사진이 없는 경우에도 204다. |
| 기존 `GET /pets`, `GET /pets/{petId}` | 기존 필드에 `profilePhoto: null` 또는 `{ assetId, contentUrl, thumbnailUrl }`을 추가한다. URL은 인증된 API 상대 경로다. |
| `GET /pets/{petId}/profile-photo/{assetId}/content`, `GET /pets/{petId}/profile-photo/{assetId}/thumbnail` | 반려동물과 실제 연결된 사진 일치 여부를 확인한 뒤 파일을 스트리밍한다. 공개 스토리지 경로는 제공하지 않는다. |

- pet은 반려동물당 하나의 nullable 사진 자산 ID를 저장한다. 기존 행은 사진 없음으로 읽힌다. 파일·변형·상태·참조 수·정리 작업은 media가 소유한다.
- pet은 소유권과 현재 사진 연결을 검사한 뒤 media의 `GetAttachedMediaUseCase`를 호출한다. media는 `PET_PROFILE` 용도·pet 일치·READY 상태로 파일 제공을 다시 확인한다. 연결 전 preview와 연결 후 부모 경로의 권한을 각각 유지한다.
- 교체·제거·반려동물 삭제는 동일한 pet 행을 기준으로 기존 버전 검사를 사용한다. 먼저 pet의 소유권과 관찰한 버전을 검증하고 필요한 pet 잠금을 얻는다. 기존·신규 미디어 자산은 기존 미디어 참조 포트의 ID 오름차순 잠금 규칙으로 처리한다.
- 연결 변경을 저장·flush하여 미디어가 같은 트랜잭션에서 이전 연결이 사라진 것을 확인할 수 있게 한다. 참조 변경·정리 작업 등록도 같은 트랜잭션에서 수행한다. 사용 여부 조회는 pet 입력 포트에서 제공하고 media가 pet 행에 추가 잠금을 걸지 않는다.
- pet 삭제는 기존 연관 기록 확인과 DB 제약을 유지한다. 사진 연결 제거와 미디어 참조 해제는 pet 삭제가 실패하면 함께 롤백한다. 물리 파일은 기존 비동기 정리 작업에서 삭제한다.

## 범위 밖

- 여러 장 사진, 품종 자동 판별, 가족 사진 열람과 소유자 이전 시 사진 권한([#133](https://github.com/likelion-backendschool-9th/pawmento/issues/133)).
- 엽서가 프로필 사진을 소비하는 계약과 사진 수명([#127](https://github.com/likelion-backendschool-9th/pawmento/issues/127)).
- 프론트는 위 응답을 바탕으로 기본 이미지·처리 중·재시도를 표시한다. 이번 백엔드 계획 단계에서는 화면이나 기존 #85 흐름을 변경하지 않는다.

## 작업 순서

1. **미디어 용도와 사용 여부 확인** — S2·S3·S8. media의 웹 요청·도메인·입력 포트와 `MediaReferenceAdapter`, 실제 pet 연결을 확인하는 pet 입력 포트를 구현 대상으로 잡는다. 미디어 담당 리뷰는 IMAGE 전용 정책 적용과 참조 보호에 집중한다.
2. **최소 연결·조회 경로** — S1·S4·S5. pet 데이터 모델·저장소, 소유권을 확인하는 사진 유스케이스, 기존 `PetController`·응답, media 호출 어댑터를 연결한다. 기존 사진 없는 목록·상세와 연결 전 업로더 preview를 함께 확인한다.
3. **교체·제거·반려동물 삭제** — S6·S7·S9. pet과 media의 실제 저장 경계를 사용한다. PostgreSQL/Testcontainers에서 서로 다른 트랜잭션으로 경합을 재현하고, 종료 뒤 새 트랜잭션에서 연결·참조 수·정리 작업을 확인한다.

## 정한 것

- 사진 실패와 반려동물 등록은 독립이다. pet 등록 → media 업로드 → READY 확인 → 연결 순서를 사용한다. JPEG·PNG·WebP, 15MiB, 4천만 픽셀, EXIF 제거본·썸네일을 제공하며 GPS 후보는 만들지 않는다. [기능 담당 답변](https://github.com/likelion-backendschool-9th/pawmento/issues/130#issuecomment-7046460972)
- 소유자만 사진을 변경·열람한다. 사진만 있는 반려동물은 삭제할 수 있으며, 마지막 참조는 기존 media 정리 절차로 넘긴다. [미디어 담당 답변](https://github.com/likelion-backendschool-9th/pawmento/issues/130#issuecomment-7047167811)
