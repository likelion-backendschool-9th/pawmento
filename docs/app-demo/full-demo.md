# P1~P3 공통 앱 데모 확장

기준 이슈 [#12](https://github.com/likelion-backendschool-9th/pawmento/issues/12)와 [P1 계획](p1-implementation.md)을 확장한다. 사용자가 P1~P3 전체 화면·데모 동작을 명시적으로 선택했으며 질문+답변 보존, 원본 이미지의 로고 사용, PC 웹앱 레이아웃을 요청했다.

## 요구사항

- #12-R5 질문 기록은 질문 ID·질문 본문·답변·기억 날짜를 함께 저장한다. 수정 시 원 질문을 보존하고 홈·오늘의 질문·질문 상세에서 표시한다. 자유 기록인 다이어리는 일기/달력에서 조회하며 질문 답변과 해당 첨부를 섞지 않는다. (고침 #12: 질문 답변을 다이어리와 분리하는 최종 의도 반영)
- #12-R6 원본 이미지는 워드마크와 결합한 로고로 사용한다. PC와 모바일 모두 일상·정원 공통 상단 탐색·사진 전시형 홈을 사용하며 색감으로 구분한다. 헤더의 반려동물 선택으로 저장된 아이별 모드를 불러오고, 반려동물 관리 카드에서만 소유자가 해당 아이의 모드를 변경한다. 홈의 중복 바로가기는 제공하지 않는다. (고침 #12: 공통 레이아웃과 반려동물 관리 진입으로 정리)
- #12-R7 P2 모드 전환, 과거 오늘·무작위 기억, 미디어 첨부, 질문 이력, 커뮤니티 CRUD·댓글·좋아요·검색·신고·내 활동을 연결한다. 커뮤니티는 전체 보기 없이 카테고리별로 표시하고 기본값은 반려 생활이다. 추모 글은 해당 카테고리를 선택한 경우에만 표시하며 검색·정렬·내 활동도 카테고리 안에서 동작한다. (고침 #12: 추모 글의 비의도적 혼합 노출 방지)
- #12-R8 P3 정원 전용 우체통은 무작위 기록 한 개의 상황과 반려견 참조 사진을 연결해 준비된 수채화 장면을 표시하며 생성 진행/완료/실패·보관·양면 HTML 다운로드를 제공한다. 가족 초대·참여 확인·역할 변경·공유 해제를 데모로 제공하고 실제 AI·메일 발송·다른 기기 공유로 표시하지 않는다. (고침 #12: 원본 사진 재사용 대신 상황별 수채화 장면 데모와 랜덤 한 기록 흐름 반영)
- #12-R9 관리자 데모에서 신고 처리·질문 풀·공지·데모 회원 상태를 확인하고 변경한다. 설치 가능 브라우저에서 설치 안내와 오프라인 안내를 제공한다. 자동 푸시는 만들지 않는다.

## 확인 시나리오

- #12-S6 [테스트] 질문 스냅샷·답변이 날짜별 조회와 수정 이후 보존되고 다이어리 조회에서 제외됨. [직접] 오늘의 질문→답변 작성→질문 상세/이력 확인, 다이어리 일기/달력에는 자유 기록만 표시. (고침 #12: 질문 답변과 자유 기록을 별도 탐색)
- #12-S7 [테스트] 두 아이의 독립된 모드와 프로필 수정 후 기록 보존. [직접] 반려동물 관리→대상 아이 모드 변경→홈, 헤더에서 아이 선택 시 해당 모드 복원, ACTIVE 우체통 미노출·GARDEN 우체통 표시. (고침 #12: 설정 대신 반려동물 관리에서 아이별 변경)
- #12-S8 [테스트] 게시글·댓글 작성자 제한, 좋아요·신고 중복 방지. [직접] 기본/잘못된 카테고리에서 반려 생활만 표시, 추모 선택·카테고리 내 검색/정렬·상세 복귀·작성 기본값·글/댓글 CRUD·내 활동. (고침 #12: 전체 카테고리 조회 제거)
- #12-S9 [테스트] 랜덤 기록 하나·장면 분기·원본 참조·생성 상태·실패·재시도·엽서 보관. [직접] 정원→우체통→기억 뽑기→수채화 데모 엽서→양면 상세/다운로드. (고침 #12: 무작위 기억과 상황별 샘플 그림을 사용하는 최종 흐름 반영)
- #12-S10 [테스트] 초대 역할·만료·중복 참여 및 역할 변경. [직접] 링크 복사·데모 참여·역할 변경·공유 해제.
- #12-S11 [직접] 사진·영상·음성 선택/재생과 일기 상세의 첨부 조회, 자동 재생 없음. (고침 #12: 다이어리를 일기/달력 두 탭으로 정리하고 첨부는 일기에서 조회)
- #12-S12 [직접] 관리자 신고 처리·질문/공지 관리, 설치/오프라인 안내.
- #12-S13 [명령] lint·타입·빌드. [직접] PC 1440/1280, 태블릿768, 모바일390/360px와 모든 메뉴 진입.

## 경계와 저장

기존 workspace 코어는 기록·미디어·모드를 담당한다. 새 life application은 커뮤니티·엽서·가족·운영의 데모 상태를 포트로 읽고 쓰며 브라우저 구현은 outbound에 둔다. 같은 브라우저 안에서만 데모 커뮤니티·초대 상태가 공유되고, 서버 권한·실제 AI 생성·외부 전송은 제공하지 않는다. 실제 파일 업로드는 브라우저 저장 한도 내이며 실패 시 입력을 보존한다.

## 라우팅 경계 결정

- App Router의 `(auth)`·`(app)` 페이지가 각 화면을 직접 import하고 `(app)/layout.tsx`에서 인증·Shell을 공유한다. 브라우저 저장소를 사용하는 inbound 화면은 Client Component로 유지한다. 로딩·오류·없는 경로는 프레임워크 경계로 처리한다. (고침 #12: 중앙 라우트 분기와 전체 화면 정적 import 제거)
- 미저장 폼은 링크·탭 닫기와 헤더/전체 메뉴의 반려동물 선택 이동에서 확인한다. 취소 시 저장소의 선택 아이와 작성 입력을 유지한다. (고침 #12: 직접 router 이동 전에 동일한 이탈 확인 적용)
