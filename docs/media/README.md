## 범위와 책임

- 이미지 선택, 영상 선택, 브라우저 음성 녹음 결과를 파일로 업로드한다. 녹음도 하나의 AUDIO 파일이며 별도의 답변 본문 형식으로 저장하지 않는다.
- 실제 파일은 비공개 객체 저장소, DB에는 메타데이터와 첨부 관계를 저장한다. base64/data URL·브라우저 blob URL을 영구 파일 주소로 저장하지 않는다.
- 업로드·검증·미리보기·가족 열람·미사용 파일 정리·삭제 재시도를 이번 범위에 포함한다.
- `media`는 파일 상태·검증·저장·조회 URL을 담당하고, diary/question은 각각 본문·작성자·첨부 순서와 부모 자원 권한을 담당한다. 질문과 다이어리 저장소는 통합하지 않는다.
- 초기 대상은 `DIARY_ATTACHMENT`, `QUESTION_ANSWER_ATTACHMENT`다. 프로필·커뮤니티·AI 생성물은 별도 정책을 정한 뒤 확장한다.

## 저장 방식 제안

배포 저장소는 비공개 S3, 로컬·자동 테스트는 저장소 포트의 로컬/가짜 어댑터를 쓰는 안으로 시작한다. 버킷 생성·클라우드 비용·실제 배포 설정은 이 문서 작성에 포함하지 않는다.

업로드는 **JSON으로 업로드 세션 발급 → 브라우저에서 임시 객체에 직접 업로드 → 서버 검증 완료 → 글에 파일 ID 연결**로 제안한다. 큰 영상을 애플리케이션 JSON 본문에 담지 않고, 저장소 어댑터 교체가 question/diary 업무를 바꾸지 않게 한다. 공통 API는 JSON 인증 요청을 유지하며 저장소 PUT에는 앱 인증 쿠키를 보내지 않는다.

S3 presigned URL은 특정 객체 작업을 임시로 허용하는 주소다. 같은 키로 다시 업로드하면 기존 객체를 덮어쓸 수 있으므로 **업로드용 임시 키와 검증 완료 파일의 최종 키를 분리**한다. 주소를 발급했다는 이유만으로 업로드 완료·형식 검증을 통과한 것으로 보지 않는다. [AWS 공식 문서](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)

## 업로드부터 저장까지

1. 로그인한 OWNER/EDITOR가 대상 아이·용도·파일명·신고 MIME·예상 크기를 JSON으로 요청한다. 서버가 현재 가족 쓰기 권한·신고값·업로드 건수/용량 한도를 먼저 확인한다.
2. 서버가 임의의 `assetId`, 재사용하지 않는 임시 `objectKey`, 업로드 만료 시각을 생성하고 PENDING 자산을 저장한다. 파일명이나 클라이언트 경로를 저장 키로 쓰지 않는다.
3. 브라우저가 임시 업로드 주소로 실제 바이너리를 PUT한다. 진행률·취소·재시도를 표시한다. 업로드 실패 시 글 입력과 다른 첨부는 유지한다.
4. 업로더가 완료 API를 호출한다. 서버가 PENDING을 PROCESSING으로 조건부 변경하고 검증 작업을 같은 DB 트랜잭션의 작업 테이블에 등록한다. 중복 완료 호출은 같은 작업/결과를 반환한다.
5. 작업자는 임시 객체를 제한된 임시 공간으로 읽어 실제 크기·시그니처·파일 파싱·재생 시간을 검증한다. HEAD의 Content-Type이나 클라이언트 파일 확장자만 믿지 않는다. **검증한 동일 바이트**를 새 최종 비공개 키에 저장한다. 검증 뒤 임시 키를 그대로 서비스하거나 검증하지 않은 바이트를 다시 복사하지 않는다.
6. 최종 저장 성공 후 READY로 변경하고 검증한 메타데이터를 기록한다. 실패는 REJECTED 및 정리 대상으로 전환한다. 네트워크 I/O·파싱 중 DB 잠금을 오래 잡지 않고, 작업은 임대 시간·재시도·중복 실행을 고려한다.
7. 프론트는 상태 API에서 READY를 확인한 뒤 `attachmentIds`를 일기/답변 저장 JSON에 보낸다. PROCESSING·실패 파일이 있으면 제거하거나 재시도할 때까지 저장을 막는다. 녹음 중·업로드 중에는 저장 완료로 표시하지 않는다.
8. diary/question 서비스는 가족 권한·부모 자원 권한과 각 자산의 업로더·아이·용도·READY 상태를 **저장 시 다시** 확인한다. 글·첨부 연결·자산 참조 수 변경을 같은 DB 트랜잭션으로 저장한다.
9. 질문 답변은 이 저장이 성공한 시각을 등록일로 삼고 가족 공통 질문을 한 번만 진행시킨다. 파일 업로드 완료나 녹음 시작 시각은 답변 등록일이 아니다. 첨부 연결 실패 시 답변·질문 진행도 함께 롤백한다.

최종 저장 성공 후 DB 갱신 실패, 임시 파일 업로드 후 세션 만료, 작업자 중단은 정리 작업에서 복구한다. 임시 키·최종 키 모두 서버가 추적 가능한 값으로 생성해 고아 객체를 찾을 수 있게 한다. READY 자산의 실제 바이트는 이후 덮어쓰지 않고 교체는 새 자산으로 수행한다.

## 데이터 구조와 상태

`com.pawmento.media`의 `MediaAsset`과 `media_asset`을 둔다.

| 필드 | 의미 |
| --- | --- |
| `id` | 외부에 노출하는 파일 ID |
| `uploader_member_id`, `pet_id`, `purpose` | 누가, 어느 아이의 어떤 기능에 올렸는지. 생성 후 변경 불가 |
| `media_type` | IMAGE / VIDEO / AUDIO. 검증 결과로 확정 |
| `original_filename` | 화면 표시용 이름. 경로로 사용하지 않음 |
| `declared_mime_type`, `declared_size_bytes` | 업로드 요청값. 검증 완료 전 신뢰하지 않음 |
| `mime_type`, `size_bytes`, `duration_ms`, `width`, `height` | 실제 파싱한 값. 해당하지 않는 항목은 null |
| `temporary_object_key`, `object_key`, `checksum` | 비공개 저장 위치와 검증한 바이트의 해시. URL과 자격 증명 저장 안 함 |
| `status`, `failure_reason`, `version` | 상태·사용자 안내 가능한 실패 사유·조건부 갱신 버전 |
| `reference_count` | 일기/답변 첨부 연결 수. 0일 때만 미사용 정리 가능 |
| `created_at`, `upload_expires_at`, `ready_at`, `unattached_expires_at` | 세션·미연결 파일 수명 |
| `deletion_requested_at`, `deleted_at` | 삭제 작업 이력. 상세 재시도는 작업 테이블에 보관 |

상태는 `PENDING → PROCESSING → READY`, 실패하면 `REJECTED`, 정리 대상은 `DELETING → DELETED`다. READY가 ‘글에 연결됨’을 뜻하지는 않는다. 연결은 `reference_count`와 도메인별 첨부 테이블로 구분한다.

- diary의 `record_attachment(record_id, asset_id, sort_order)`와 question의 `question_answer_attachment(answer_id, asset_id, sort_order)`를 유지한다. 각 테이블에 부모+파일 중복 및 부모+순서 유니크 제약을 둔다.
- 참조 수 변경은 media 입력 포트를 통해 호출하고 부모·첨부 행 변경과 같은 DB 트랜잭션으로 수행한다. 저장소 API 호출은 이 트랜잭션 밖이다. 실패 시 카운트만 남지 않아야 한다.
- 참조 획득과 정리 작업은 같은 자산 행의 잠금/조건부 갱신 규약을 따른다. 정리가 먼저 DELETING으로 바꾸면 연결을 거부하고, 연결이 먼저 성공하면 정리는 건너뛴다.
- 초기에는 같은 자산을 같은 아이·같은 용도·같은 업로더의 여러 글에 재사용할 수 있도록 제안한다. 다른 용도/아이로 복사하려면 새 업로드가 필요하다. 여러 연결 중 하나를 삭제했다고 원본을 지우면 안 된다.
- 참조 수와 실제 연결의 정합성 확인·복구 작업을 둔다. 잘못된 카운트만으로 실제 참조 파일을 삭제하지 않도록 삭제 직전 각 도메인의 참조 확인 포트를 사용한다.

## API 계약 제안

경로는 공통 `/api/v1` 접두사를 뺀 표기다. `WebConfig`가 접두사를 붙이므로 컨트롤러에 중복 작성하지 않는다.

| 요청 | 입력 | 응답 |
| --- | --- | --- |
| `POST /pets/{petId}/media/uploads` | JSON: `purpose`, `filename`, `mimeType`, `sizeBytes` | 201: `assetId`, `status`, `upload: {url, method, headers, expiresAt}` |
| `POST /pets/{petId}/media/{assetId}/complete` | 빈 JSON 객체 | 처리 중 202, 이미 READY면 200. 자산 상태 응답 |
| `GET /pets/{petId}/media/{assetId}` | 없음 | 200: 상태·검증된 메타데이터·실패 사유. 상태 조회로 글은 생성하지 않음 |
| `POST /pets/{petId}/media/{assetId}/preview-url` | 빈 JSON 객체 | 200: 미연결 READY 자산의 업로더용 임시 열람 주소·만료 시각 |
| `DELETE /pets/{petId}/media/{assetId}` | 없음 | 미연결 파일 취소/정리 예약 202. 이미 삭제됨도 동일. 연결된 파일은 409 |

가족 열람은 **부모 글의 권한과 실제 첨부 관계**로 확인한다.

- `POST /pets/{petId}/diaries/{recordId}/attachments/{assetId}/access-url`
- `POST /pets/{petId}/question-answers/{answerId}/attachments/{assetId}/access-url`

두 API는 빈 JSON 객체를 받고, 부모 도메인이 현재 가족 열람 권한과 첨부 관계를 확인한 뒤 media 내부 포트로 짧은 URL을 발급한다. 응답은 `{url, expiresAt, mimeType}`다. 임의 `assetId`만 알거나 같은 아이의 다른 업로드를 안다고 접근할 수 없다. 메타데이터 조회 API는 업로더에게만 열고 가족은 부모 상세의 첨부 메타데이터를 받는다.

다이어리·답변의 `attachments` 응답은 `{assetId, type, filename, mimeType, sizeBytes, durationMs, width, height, sortOrder}`다. DB에 임시 URL을 저장하지 않는다. 표시가 필요할 때 열람 API를 부르고 만료 시 재발급한다. 영상·음성은 실제 재생에 필요한 Range 요청·CORS·Content-Type을 검증한다.

- 예시 TTL: 업로드 주소 10분, 열람 주소 5분, 미연결 READY 보관 24시간. 모두 설정으로 관리하며 제안값이다.
- 만료된 주소로 새 파일을 같은 자산에 덮어쓰는 기능은 두지 않는다. 업로드 재시도는 유효한 PENDING 세션에서만, 만료/검증 실패는 새 자산으로 요청한다.
- 공통 오류 `{code, message}`를 따른다. 401 미로그인, 403 VIEWER 쓰기/타인 업로드 조작, 404 비가족·없는 자원·부모와 무관한 첨부, 400 입력/형식 오류, 409 상태·용도·참조 충돌. 크기 초과 413·형식 미지원 415는 공통 에러 처리에 명시적으로 추가할 구현 항목이다. 비동기 검증 실패는 상태 REJECTED로 조회된다.

## 형식·크기·녹음 처리

| 분류 | 초기 허용안 | 제한 제안 |
| --- | --- | --- |
| IMAGE | JPEG, PNG, WebP | 파일당 10MiB, 최대 4천만 픽셀. 방향 보정·EXIF 위치 정보 제거한 서비스본 생성 |
| VIDEO | MP4(H.264/AAC), WebM(VP8/VP9와 Opus/Vorbis) | 파일당 100MiB, 재생 3분 |
| AUDIO | WebM/Opus, Ogg/Opus, MP4/AAC(M4A), MP3 | 파일당 20MiB, 재생 5분 |
| 공통 | 한 일기/답변에 종류 합쳐 최대 5개 | 첨부 합계 최대 200MiB |

이 표는 제품 정책 초안이며 프론트 localStorage의 2MB/30초 한도를 서버 정책으로 복사한 것이 아니다. 배포 환경의 처리 성능·저장 비용을 확인해 확정한다. 허용 범위와 실제 오류는 서버가 최종 결정한다.

- 확장자·신고 MIME·실제 컨테이너/코덱을 구분한다. SVG/HTML·실행 파일·파싱 실패·정책 초과 파일은 거부한다. 임시 디스크·파서 실행 시간·메모리 한도도 둔다.
- 녹음은 브라우저가 지원하는 MIME으로 생성한다. 실제 `Blob.type`을 요청하고 파일 확장자만 임의로 mp3로 바꾸지 않는다. 서버가 미지원 형식이면 녹음 전 안내하거나 지원 형식으로 다시 녹음한다.
- 이미지 서비스본의 메타데이터 제거·방향 보정을 포함한다. 영상·음성의 위치/기기 메타데이터 제거는 파서·리먹싱 도구로 수행하고 정책을 검증한다. 일반 조회로 원본을 공개하지 않는다.
- 전체 영상 트랜스코딩·화질별 스트리밍은 초기 범위 밖이다. 지원 코덱의 재생을 실제 PC·모바일에서 확인하고 미지원 코덱은 처리 가능한 것으로 표시하지 않는다.
- 썸네일은 이미지 축소본, 영상은 대표 프레임을 만드는 안으로 한다. 오디오 파형·전사는 후속이며 음성 파일·재생 시간과 재생 기능은 이번 범위다.

## 가족 권한과 보관

- 업로드 세션 생성·완료·글 저장 때마다 현재 멤버십과 쓰기 권한을 검사한다. 업로더 ID는 인증 회원에서 정하고 요청 본문으로 받지 않는다.
- 새 첨부는 본인 업로드만 연결한다. 수정 시 기존에 유효하게 연결된 첨부를 유지하는 동작과 타인의 새 파일을 추가하는 동작을 구분한다.
- 가족은 접근 가능한 일기/답변에 연결된 파일만 읽는다. 업로드 중·미연결 파일은 업로더만 볼 수 있다. 작성자와 업로더는 서로 다른 책임으로 보관한다.
- 가족 탈퇴 후 새 URL 발급과 모든 변경은 거부한다. 이미 발급된 서명 URL은 만료 전까지 사용될 수 있으므로 짧은 TTL을 사용한다. 즉시 차단이 필요하면 인증된 스트리밍 프록시로 바꾸는 별도 결정이 필요하다.
- 버킷은 비공개다. 저장소 자격 증명은 서버 환경/실행 역할로만 설정하고 업로드·열람 URL을 로그에 남기지 않는다. 허용 프론트 출처만 저장소 CORS에 등록한다.

## 취소·삭제·실패 복구

- 글 저장 전 취소는 미연결 파일 삭제 API로 예약하고, 호출이 없더라도 만료 배치가 정리한다. 취소는 일기·질문 답변 데이터를 만들지 않는다.
- 첨부 변경은 ID 전체 목록으로 교체한다. 유지·추가·제거 차이를 계산해 참조 수를 조정한다. 글 저장 실패 시 원래 연결과 참조 수를 유지한다.
- 글 삭제는 부모·첨부 연결 삭제와 참조 감소·삭제 작업 등록을 같은 DB 트랜잭션으로 수행한다. 작업 등록에는 outbox/삭제 작업 테이블을 사용해 프로세스 중단에도 누락되지 않게 한다.
- 마지막 참조가 사라지면 자산을 DELETING으로 표시하고 작업자가 실제 객체·썸네일·임시 객체를 삭제한다. 저장소 장애는 재시도하며 글을 되살리지 않는다. 이미 없는 객체 삭제는 성공으로 취급한다.
- 만료 PENDING, 장시간 PROCESSING, 미연결 READY, REJECTED, 저장소만 남은 고아 객체를 정리한다. 작업 임대·시도 횟수·최종 오류를 기록하고 영구 실패는 운영자가 확인할 수 있게 한다.
- 저장소의 임시 경로 lifecycle은 보조 수단이다. DB 정합성 확인 없이 최종 경로 전체에 만료 정책을 걸어 첨부된 파일을 삭제하지 않는다.

## 헥사고날 경계·구현 순서

`com.pawmento.media` 아래 domain/application/adapter 규칙을 따른다. JPA 엔티티·S3 SDK·MultipartFile·브라우저 MIME 처리 객체가 핵심 계층으로 새지 않도록 한다.

1. 개발 이슈·형식/용량·권한·저장소 계약 확정. 실제 버킷·배포 키 준비는 별도 설정 작업이다.
2. `MediaAsset` 상태·저장소 포트·S3/테스트 어댑터, JSON 업로드 세션 API와 만료 처리.
3. 검증 작업자·완료/상태 조회·불변 최종 저장·썸네일·비공개 열람.
4. `AcquireMediaReferencesUseCase`, `ReleaseMediaReferencesUseCase` 등 내부 포트와 트랜잭션 규약을 정의해 diary/question 첨부 저장과 연결.
5. 취소·미사용 정리·outbox 삭제·실패 재시도·참조 정합성 검사.
6. 프론트 공통 업로더·미리보기·녹음·재생과 일기/답변 저장 흐름 연결.

media에서 부모 참조 확인이 필요하면 출력 포트와 각 도메인의 입력 포트를 조합하는 어댑터를 사용한다. 도메인끼리 서로의 JPA 저장소를 직접 참조하거나 Spring 서비스 빈을 순환 주입하지 않는다. 같은 DB 트랜잭션을 공유할 내부 포트와 정리 검사의 의존 방향을 구현 이슈에서 명시한다.

## 아직 정하지 않은 것과 범위 밖

- S3 적용·버킷 리전·계정·비용·개발용 저장소와 용량/재생 시간/TTL 제안값을 확정해야 한다.
- 악성코드 검사 도구·미디어 파서·EXIF 제거 도구·이미지/영상 썸네일 도구와 배포 자원 한도를 정한다. 선택한 실제 라이브러리·도구의 공식 문서와 라이선스는 구현 이슈에서 확인한다.
- 대용량 multipart 업로드, 영상 트랜스코딩/HLS, CDN, 음성 전사·파형 분석은 초기 범위 밖이다. 이미지·영상·음성 업로드 및 재생은 포함한다.
- 아이/회원 삭제와 가족 탈퇴 시 파일·작성자 데이터 보존은 각 도메인 정책과 맞춘다. 즉시 권한 회수와 짧은 서명 URL의 차이는 제품 정책으로 확인한다.
