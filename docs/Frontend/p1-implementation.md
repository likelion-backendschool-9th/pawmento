# P1 프론트엔드 구현 계획

후속 범위: 사용자가 P1~P3 전체 프론트엔드 데모로 확장을 요청했다. 현재 작업 범위와 추가 시나리오는 [전체 데모 계획](full-demo.md)을 따른다. 아래는 최초 P1 계획의 배경을 보존한다.

관련 이슈: [#12](https://github.com/likelion-backendschool-9th/pawmento/issues/12). 사용자가 P1 범위, 계획 작성과 작업 브랜치 생성을 승인했다.

## 요구사항

- #12-R1 기존 Next.js App Router와 React/TypeScript를 유지한다. domain → application ports/use cases → outbound adapter, inbound React 화면과 composition root를 분리한다.
- #12-R2 로그인·가입·로그아웃·내 정보, 반려동물 등록·선택·수정, 질문 일기 및 자유 기록 CRUD, 달력·타임라인을 구현한다.
- #12-R3 실제 서버 계약이 없는 기능은 명시적인 브라우저 데모로 제공한다. 비밀번호·인증 토큰을 영구 저장하지 않는다. 데모 계정은 현재 탭에서만 유효하며 기록은 계정별 브라우저 저장소에 보관한다.
- #12-R4 디자인 토큰의 아이보리·세이지, PC 우선 반응형, 키보드 접근과 로딩/오류/빈 상태를 지원한다.

## 화면 디자인

공개 진입 화면은 왼쪽 브랜드 메시지와 오른쪽 정원 모티프의 편집형 구성으로 한다. 앱은 상단 브랜드/주요 탐색, 반려동물 선택, 중앙 오늘의 질문과 최근 기록, 우측 프로필·작은 달력으로 구성한다. 모바일은 단일 열과 하단 탐색을 쓴다. 일기 작성은 사진 영역과 답변 폼을 배치하고 상세에서 수정·삭제한다. 업로드 사진이 기록의 중심이며 브랜드 장식은 정원 아치·꽃·발자국으로 제한한다.

## 데이터와 경계

- Pet: id, name, species, breed, birthday, photoUrl, mode(ACTIVE 확장 슬롯).
- Record: id, petId, type(DIARY/TEXT/PHOTO), recordedDate, createdAt, updatedAt, body, question, photoUrl.
- Account: id, email, nickname. 브라우저 세션과 계정별 저장 영역을 분리한다.
- 포트: QuestionRepository(날짜별 질문), WorkspaceRepository(반려동물·기록), AuthRepository(현재 탭의 데모 계정·세션). 사진 선택·파일 제한·Data URL 변환은 inbound 브라우저 어댑터가 담당한다.
- use case: 반려동물 검증·등록/수정/선택, 일기 중복 방지·기록 검증/CRUD, 날짜별/페이지별 조회, 로그인/가입/정보 수정.
- 현재 단계는 HTTP 엔드포인트를 가정하지 않는다. composition에서 브라우저 데모 어댑터를 주입하고 서버 계약 확정 시 HTTP 구현체로 교체한다.

## 시나리오와 확인 방법

- #12-S1 [테스트] 가입 필드 검증, 로그인/로그아웃과 보호 화면 접근. [직접] 진입 → 데모 시작 → 홈 → 로그아웃.
- #12-S2 [테스트] 두 반려동물 전환 시 기록 분리, 이름/종 검증, 등록·수정. [직접] 선택기·프로필 편집.
- #12-S3 [테스트] 질문 일기 저장·중복 방지·수정·삭제, 저장 실패 시 원본 보존. [직접] 홈 → 작성 → 상세 → 수정 → 삭제 → 홈 반영.
- #12-S4 [테스트] 날짜 필터·반려동물 필터·페이지 추가 조회, 잘못된 날짜 거부. [직접] 기록 작성 → 달력 날짜 클릭 → 타임라인.
- #12-S5 [명령] lint·TypeScript·프로덕션 빌드. [직접] 1440/768/390/360px 화면과 키보드 탐색·파일 제한·비어 있는 목록·잘못된 입력 확인.

## 범위 밖과 가정

실제 서버 인증·이메일 중복 API·서버 업로드·권한 보장·서버 연동은 포함하지 않는다. 데모는 장치·탭 간 인증을 제공하지 않는다. P2/P3 화면과 실제 AI 호출·푸시·PWA는 제외한다. 반려동물 삭제의 연관 기록 정책은 미정이므로 삭제 기능은 보류한다. 오늘 날짜는 Asia/Seoul 기준으로 통일한다. 사용자가 제공한 정원·코기 원본 PNG를 그대로 사용한다. 레퍼런스에 맞춰 크림색 카드, 올리브색 버튼, 큰 사진과 꽃 장식을 적용한다. (고침 #12: 사용자가 원본과 화면 레퍼런스를 기준으로 디자인 수정을 요청함)

## 작업 순서

1. 순수 도메인·포트·유스케이스·브라우저 어댑터와 회귀 테스트.
2. 디자인 토큰·공통 레이아웃·공개 및 인증 화면.
3. 반려동물·홈·기록 CRUD·달력·타임라인·내 정보.
4. 시나리오 검사와 반응형 확인.
