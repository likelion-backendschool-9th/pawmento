# PawMento 디자인 토큰 · UI 가이드

현재 저장소의 프론트엔드 구현을 기준으로 정리한 디자인 명세다. 기준일은 2026-11-18이며, 이번 갱신은 화면 변경 없이 문서만 정리한다.

## 기준 파일과 적용 범위

| 기준 | 소스 | 담당 |
|---|---|---|
| 공통 변수 | [tokens.css](../../frontend/styles/tokens.css) | 색상, 모드별 의미 토큰, 본문 글꼴, 카드 그림자 |
| 공통 요소 | [globals.css](../../frontend/app/globals.css) | 버튼, 입력, 브랜드, 대화상자, 첨부, 포커스 |
| 기능 탐색 | [AppShell.tsx](../../frontend/features/shell/components/AppShell.tsx) | 반려동물 선택, 모드에 따른 메뉴 구성 |
| 공간 레이아웃 | [SpaceShell.module.css](../../frontend/features/shell/components/SpaceShell.module.css) | 헤더, 콘텐츠 폭, 배경, 전체 메뉴, 모바일 탐색 |
| 홈 | [HomeScreen.module.css](../../frontend/features/pet/components/HomeScreen.module.css) | 소개 영역, 프로필, 사진 전시, 정원 우체통 안내 |
| 업무 화면 | [Workspace.module.css](../../frontend/features/shell/components/Workspace.module.css) | 기록, 달력, 반려동물 관리 등 화면별 배치 |
| 엽서 | [PostcardPaper.module.css](../../frontend/features/postcard/components/PostcardPaper.module.css) | 종이, 장면 그림, 편지, 우표와 소인 |

`globals.css`에는 같은 선택자를 뒤에서 덮어쓰는 규칙이 있다. 이 문서의 공통 규격은 뒤쪽 규칙까지 반영한 값이며, 화면별 CSS 모듈과 선택자 우선순위에 따라 달라질 수 있다. 모든 색상·간격·모서리가 변수로 통일된 상태는 아니다. 아래의 **CSS 변수**와 **컴포넌트 개별 값**을 구분해서 사용한다.

## 공간과 시각 방향

일상과 정원은 개방적인 PC 레이아웃, 사진 전시형 홈, 같은 탐색 구조를 공유한다. 일상은 연녹색과 올리브, 정원은 크림과 파스텔 보라로 구분한다. 수채화 배경 위에 읽기 쉬운 밝은 표면을 겹치고, 사진과 엽서는 종이의 여백·얕은 그림자·가벼운 기울기로 표현한다.

| 구분 | 일상 · ACTIVE | 정원 · GARDEN |
|---|---|---|
| 주요 색 | 올리브 녹색 | 차분한 보라 |
| 바탕 | 연녹색 워시 | 크림색 워시와 연보라 틴트 |
| 브랜드 그림 | 코기 | 정원 문 |
| 공통 기능 | 홈, 다이어리, 오늘의 질문, 커뮤니티, 가족 공동 기록, 관리 | 동일 |
| 추가 기능 | — | 기억의 우체통과 홈 안내 |

모드는 **반려동물 관리에서 각 아이별로 변경**하며 소유자만 변경할 수 있다. 헤더의 반려동물 선택은 해당 아이에게 저장된 모드를 불러오는 동작이다. 설정이나 홈에 별도 모드 스위치를 추가하지 않는다. 현재 홈은 공통 `HomeScreen`을 사용하며 꽃나무 쪽지·별도 정원 편지 화면은 기준에 포함하지 않는다.

| `--mode-card` | `#fffefbe8` | `#fffdf7e8` | 모드별 반투명 카드 |

| `--mode-muted` | `#6f7d62` | `#7e7987` | 모드별 보조 문구 |

| `--space-tint` | `#ecf3e4ef` | `#f1edf7ef` | 공간 배경 틴트 |
| `--hero-wash` | `#fbfef2ed` | `#fffaf4ed` | 홈 소개 영역 워시 |

8자리 HEX의 마지막 두 자리는 불투명도다. `SpaceShell`은 수채화 이미지 위에 `space-wash → space-tint(60%) → space-wash` 그라디언트를 겹친다. 홈 소개 영역은 같은 이미지에 `hero-wash → hero-tint`의 90도 그라디언트를 사용한다.

헤더, 탐색 선택 배경, 질문 배지, 정원 입력 등에는 개별 HEX 값도 남아 있다. 예를 들어 정원 셸의 입력 배경은 `#fffcf8`, 경계는 `#ded5df`로 별도 지정한다. 의미 토큰 표만으로 모든 화면의 최종 색을 판단하지 않는다.

## 글꼴과 정보 위계

`--font-sans`는 `Pretendard, SUIT, "Noto Sans KR", -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`다. 로컬 `/fonts/PretendardVariable.woff2`를 `font-display: swap`으로 불러온다. Georgia는 워드마크와 장식성 영문·일부 제목에 사용하며 한글은 본문 글꼴로 대체된다.

| 대상 | 현재 규격 | 범위 |
|---|---|---|
| 기본 본문 | 16px / 1.65, 굵기 400 | 전역 기본값 |
| 제목 기본 | 줄 높이 1.45, `word-break: keep-all` | 개별 화면에서 재정의 가능 |
| 브랜드 워드마크 | Georgia 28px / 1.1, 굵기 400 | 공통 기본값 |
| 홈 제목 | 35px / 1.6, 굵기 500 | 1050px 이하 30px, 600px 이하 25px |
| 홈 설명 | 14px / 2 | 600px 이하 12px |
| 홈 사진 전시 제목 | 21px, 굵기 500 | 600px 이하 18px |
| 질문·답변 상세 | 16px / 1.85 | 767px 이하 15px |
| 질문·답변 요약 | 13px / 1.75, 최대 2줄 | 767px 이하 12px |

글자 크기 전체를 하나의 배율로 강제하지 않는다. 입력·본문은 읽기 쉬운 위계를 유지하고, 작은 영문 장식·날짜·설명은 보조 정보로만 사용한다. 질문·답변 상세는 줄바꿈을 보존하고 긴 문자열을 감싼다. 요약의 줄임 처리는 상세 화면까지 적용하지 않는다.

전체 메뉴는 최대 860px, 최대 높이 85dvh이며 내부 스크롤을 허용한다. 메뉴 목록은 PC 3열, 모바일 1열이다. 업무 화면에는 1279px·1023px 등 별도 중단점도 있으므로 모든 페이지가 1050px·767px 두 기준만 사용한다고 가정하지 않는다.

현재 전역 간격 토큰은 없다. 위의 간격은 컴포넌트에 선언된 실제 값이며 `--space-*`라는 이름의 간격 변수를 새로 정의한 명세가 아니다. 기존 `--space-wash`, `--space-tint`는 **색상** 변수다.

## 화면별 정보 구성

### 탐색과 홈

주요 명칭은 **홈 / 다이어리 / 오늘의 질문 / 커뮤니티**다. 정원에는 **기억의 우체통**이 추가된다. 전체 메뉴에는 가족 공동 기록, 반려동물 관리, 마이페이지, 설정·설치 안내 등이 포함된다.

홈은 반려동물 소개 → 사진 전시 → 정원 우체통 안내(정원만) → 기록·질문 영역으로 이어진다. 사진 전시와 과거 같은 날 기록 등은 데이터가 있을 때 표시한다. 사진 전시는 세 장의 인화지를 가볍게 기울여 배치하고 호버 시 수평에 가깝게 들어 올린다. 반복적인 바로가기 카드 묶음을 추가하지 않는다.

### 다이어리와 오늘의 질문

다이어리는 **일기 / 달력** 탭으로 탐색한다. 질문·답변은 **오늘의 질문**에서 별도로 보여주며 자유 일기 목록·달력과 섞지 않는다. 질문은 질문 원문과 답변을 한 쌍으로 표현한다. 질문 로딩·오류·재시도·작성 동작은 빈 카드 하나로 대체하지 않고 상태에 맞게 표시한다.

기준 컴포넌트는 [ArchiveNavigation.tsx](../../frontend/components/ArchiveNavigation.tsx), [QuestionAnswer.tsx](../../frontend/components/QuestionAnswer.tsx)다. 코드의 기존 경로·타입 이름과 사용자에게 보이는 ‘다이어리 / 오늘의 질문’ 명칭은 다를 수 있으므로 UI 명칭을 기준으로 문구를 작성한다.

공통 첨부 UI에는 현재 사진·영상·음성 재생 표현이 남아 있다. 이는 화면 구현 현황이며 백엔드의 업로드 허용 형식·용량을 뜻하지 않는다. 실제 업로드 연동에서는 미디어 API 계약을 별도로 따르고, 화면 지원과 서버 지원을 혼동하지 않는다.

### 커뮤니티

전체를 섞어 보여주는 탭 없이 카테고리로 탐색한다. 기본 카테고리는 반려 생활이며, 추모 글은 해당 카테고리를 선택했을 때 표시한다. 검색·정렬과 목록 복귀에서도 선택한 카테고리 맥락을 유지한다.

### 기억의 엽서

엽서는 사진을 그대로 카드에 넣는 경험이 아니라 **기록 한 개의 상황과 반려동물 이미지를 참고해 새 장면을 그린다**는 경험을 표현한다. 현재 프론트 데모는 공원·바다·낮잠의 준비된 코기 수채화 이미지로 이를 보여주며 실제 AI 생성·사진 분석은 하지 않는다.

| 요소 | 현재 표현 |
|---|---|
| 무대 | 회색·분홍빛의 옅은 수채화 레이어, 모서리 14px |
| 종이 | `#fffdf5`, 경계 `#e6dfd1`, 겹친 종이 그림자와 미세한 질감 |
| 앞면 | 장면 그림과 여백·제목·날짜, 그림 전용 영역은 가로세로 비 1.5 |
| 뒷면 | 편지 줄·받는 이·보내는 이·우편번호·우표·소인 |
| 편지 본문 | 15px / 2.15, 줄바꿈 보존; 600px 이하 14px |
| 전환 | 앞면·뒷면 선택 상태를 `aria-pressed`로 전달 |
| 작은 화면 | 편지와 주소를 세로 배치하고 우표·주소의 내부 구성을 재배치 |

엽서의 종이·우표 색은 모드 브랜드 색과 별도로 관리한다. 화면 전반을 보라색으로 물들이거나 일반 메모 카드처럼 표현하지 않는다. 다운로드에서도 양면과 장면 그림을 유지한다.

## 접근성과 상태 표현

- 키보드 포커스는 `3px solid var(--focus-ring)`, 바깥 간격 4px이다. 활성 메뉴는 `aria-current="page"`로 표시한다.
- 본문 바로가기 링크를 유지하고, 아이콘 버튼은 눈에 보이는 문구 또는 접근 가능한 이름으로 의미를 전달한다.
- 오류·선택 상태는 색만으로 설명하지 않는다. 질문 로딩, 저장 진행, 실패와 재시도를 서로 구분한다.
- 긴 반려동물 이름·질문·답변은 줄바꿈 또는 영역에 맞는 말줄임을 사용한다. 전체 내용은 상세에서 확인할 수 있어야 한다.
- `prefers-reduced-motion: reduce`에서는 애니메이션·전환을 사실상 즉시 완료하고 자동 스크롤 효과를 줄인다.
- 모바일 고정 탐색과 토스트는 안전 영역·본문 가림을 함께 확인한다. PC 화면을 휴대전화 프레임에 고정하지 않는다.

## 구현 경계와 갱신 방법

색·글꼴·공통 상태 표현은 `styles/tokens.css`와 공통 `components`, 업무 화면 배치는 각 기능의 `features/<도메인>/components`에서 관리한다. `AppShell`은 탐색과 선택된 반려동물 맥락을 연결하고, `SpaceShell`은 공간 레이아웃을 담당한다(둘 다 `features/shell/components`). 기능의 `api`·`types`·`utils`에 HEX 값, CSS 클래스, 화면 폭 등의 표현 규칙을 넣지 않는다. (고침 #182: 프론트 구조 개편)

화면이 바뀌면 변수 선언뿐 아니라 공통 CSS의 후속 재정의, 모듈 선택자, 모드별 상속을 함께 확인한다. 새로운 공통 토큰을 도입할 때에는 실제 CSS 선언과 사용처를 먼저 맞춘 뒤 이 표에 추가한다. 문서에만 존재하는 토큰을 만들지 않는다.

[screenshots](screenshots)의 이미지는 화면 확인용 참고 자료이며 최신 구현을 보증하는 기준 파일은 아니다. 변경 화면을 다시 촬영한 경우에만 대응 캡처를 교체하고, 로고·배경·데모 사진 소스는 화면 캡처로 분류해 삭제하지 않는다. 이번 문서 갱신에서는 이미지와 캡처 파일을 변경하지 않는다.
