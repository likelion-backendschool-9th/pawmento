## 정한 것

- 카테고리는 코드가 아니라 테이블(`post_categories`)로 관리한다. 업체 후기처럼 카테고리를 더하거나 이름·순서를 바꾸거나 숨길 때 배포 없이 행만 바꾸고, 프론트엔드도 카테고리 목록 API로 탭을 만든다. 처음 카테고리는 프론트엔드 데모(#12)의 5개다: `LIFE`(반려 생활), `CARE`(건강·돌봄), `FUNERAL`(장례 정보), `MEMORIAL`(추모 방식), `MEMORY`(기억 나누기). (#21)
- 목록은 카테고리 하나를 골라서 본다. 전체 목록은 없다. 프론트엔드 설계([전체 데모](../app-demo/full-demo.md) #12-R7)와 맞추고, 추모 글이 다른 글 사이에 섞여 나오지 않게 하기 위해서다. (#21)
- 목록과 상세는 로그인 없이 볼 수 있다. 쓰기·고치기·지우기는 로그인이 필요하다. 프론트엔드 청사진의 인증 필요 경로(`/community/new`, 작성·수정)와 맞춘다. (#21)
- 글은 soft delete한다(`deleted_at`). 댓글이 붙은 뒤에도 댓글이 가리키는 글이 사라지지 않고, 신고 처리 때 지운 글을 확인할 수 있다. 지운 글은 목록·상세에서 404처럼 보인다. (#21)
- 고치기·지우기는 작성자만 한다. 작성자 확인은 도메인 객체(`Post`)가 하고, 아니면 403이다. (#21)
- 목록은 커서 기반이다(`cursor` = 마지막 글 id). 프론트엔드의 더 불러오기와 맞고, 글이 새로 올라와도 다음 페이지가 밀리지 않는다. (#21)
- 신고 접수·신고 당시 원본(스냅샷)·처리 상태는 community가 맡고, admin은 community가 제공하는 운영 포트만 쓴다. 신고 당시 글을 같은 트랜잭션에서 읽고, 처리할 때 글 숨김을 신고 처리와 한 트랜잭션으로 묶어야 하기 때문이다. 관리자 API(`/api/v1/admin/reports`)도 관리 대상 도메인인 community가 컨트롤러를 둔다. ([관리자 신고 계획](../admin/report-management.md), #92·#112)
- 신고가 쌓여도 글을 자동으로 숨기지 않는다. 관리자가 신고를 RESOLVED로 처리할 때만 숨긴다. 숨긴 글은 공개 목록에서 빠지고, 상세는 비로그인·비작성자에게 404, 작성자에게만 200과 숨김 안내를 준다. ([관리자 계획 Q3·Q5](../admin/report-management.md#q3q5--처리기각과-게시글-숨김), #92)
- 일반 사용자 화면과 API에서는 신고 여부와 건수를 신고한 본인 말고는 알리지 않는다. 관리자 조회는 관리자 계획의 계약을 따른다. 자세한 접수 규칙은 [report.md](report.md)에 있다. (#112)

## 데이터 구조 요약

`post_categories` 테이블

| 컬럼 | 설명 |
| --- | --- |
| `id` | 카테고리 id. 자동 증가 |
| `code` | API와 주소에 쓰는 코드(`CARE`). 고유 |
| `name` | 화면에 보이는 이름(`건강·돌봄`) |
| `sort_order` | 탭 순서 |
| `active` | 사용 여부. `false`면 목록에 나오지 않고 새 글을 쓸 수 없다 |

`posts` 테이블

| 컬럼 | 설명 |
| --- | --- |
| `id` | 글 id. 자동 증가 |
| `author_id` | 쓴 회원 id (`member.id`) |
| `category_id` | 카테고리 id (`post_categories.id`) |
| `title` | 100자 이내 |
| `body` | 5000자 이내 |
| `created_at` | 쓴 시각 |
| `updated_at` | 마지막으로 고친 시각 |
| `deleted_at` | 지운 시각. 지우지 않았으면 `null` |
| `version` | 동시 수정 확인용 버전(`@Version`). 고치거나 지울 때 오른다 |

## 아직 정하지 않은 것

- **업체 후기 카테고리**: README의 핵심 기능에는 있고 프론트엔드 데모에는 없다. 넣는 것은 `post_categories`에 행을 더하면 되고, 광고·비방 신고 사유를 함께 정한다.
- **카테고리 관리의 책임**: 카테고리 관리 화면을 community와 admin 중 어디가 데이터·API를 맡을지, 누가 만들지 관리자 설계(#45)에서 합의한다. 그전까지 카테고리는 DB에서 직접 바꾼다. (고침 #112: 신고·숨김의 책임은 정한 것으로 옮김)
- **작성자 닉네임**: 다른 도메인(`member`) 기능을 부르는 방식이 구조 문서에서 정해지면 목록·상세 응답에 더한다.
- **좋아요 표현**: 데모는 좋아요·북마크다. 추모 글에 "좋아요"가 어울리지 않아 화면 문구를 "함께 기억해요"처럼 바꿀지 정한다. API는 같다.
- **사진**: 파일 업로드(#33)가 생기고 multipart CSRF 처리가 정해진 뒤 더한다. 저장 방식은 정해졌다([배포 문서](../deploy.md#사진-저장-방식)).
- **기억 나누기와 기록 연결**: 기록을 글에 붙일 때 원본을 참조할지 복사(스냅샷)할지. 복사하면 원본 기록의 공개 범위와 상관없이 글이 관리된다.
