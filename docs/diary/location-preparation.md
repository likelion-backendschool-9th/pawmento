# 다이어리 수동 위치와 지도 연동 (#32, #44)

[수동 위치 계획](../map/photo-location.md#수동-위치해제-구현-계획-44-32)의 MANUAL/NONE 백엔드 구현이다. 지도 저장소의 출처·revision 열은 선행 #117 브랜치를 병합해 재사용한다. 이 작업 브랜치를 develop에 반영할 때는 #117의 포함 여부를 함께 확인한다. AUTO·사진 GPS 동의·가족 지도 공유·프론트 지도 연결은 후속이다.

## API와 응답

- 기존 `/api/v1/diaries?petId=...` 생성과 `/api/v1/diaries/{diaryId}?petId=...` 수정 body의 `location`으로만 받는다. 별도 지도 쓰기 API는 만들지 않는다.
- 생성 생략은 NONE, 수정 생략은 기존 원본 유지다. 명시적 MANUAL은 위도·경도를 모두 받고 장소명은 선택이다. 명시적 NONE은 핀을 해제한다. 위치만 PATCH도 `version`을 요구하고 부모 버전을 증가시킨다.
- 위치 JSON의 생략/명시적 null·숫자 문자열·불리언·범위 초과·서버 소유 필드 주입을 구분한다. 잘못된 입력은 400, AUTO는 미지원 409다. MANUAL은 실제 일기와 핀을 저장하며 더 이상 미지원으로 거부하지 않는다.
- 일기 생성·상세·수정·목록의 `location`에는 모드와 좌표·장소명을 담는다. 요청자가 원 작성자가 아니면 `location:null`로 반환한다. 기존 본인 지도 핀 조회와 가족 미연동 정책을 유지한다.

## 헥사고날·트랜잭션 경계

- 공개 Create/Edit 유스케이스 서비스는 `Propagation.NEVER`로 이미 열린 트랜잭션을 거부한다. 짧은 사전 읽기에서 아이·작성자·기대 버전·본문·첨부 소유권/상태를 검사한 뒤 MANUAL에 장소명이 없을 때만 주소를 조회한다.
- `CreateDiaryEntryTransaction`·`EditDiaryEntryTransaction`과 삭제 서비스는 실제 DB 작업을 수행한다. 주소 조회 뒤 권한·버전·첨부를 다시 검사하고, 부모→ID순 자산→지도 잠금 순서를 따른다. 사전 조회의 JPA 캐시를 잠금 후 재사용하지 않도록 부모와 자산을 refresh한다.
- diary 코어는 `DiaryMapPort`에만 의존한다. `adapter/out/map/DiaryMapAdapter`가 map의 조회·반영·정정·주소 조회 입력 포트에 연결하며 map 저장소를 직접 호출하지 않는다. 일기·위치 원본·첨부·media 참조·삭제 작업·지도 행이 같은 DataSource/트랜잭션에서 커밋 또는 롤백된다.
- map apply/정정은 `Propagation.MANDATORY`이고 외부 API를 호출하지 않는다. 일기별 advisory transaction lock과 행 잠금으로 없는 행의 동시 삽입까지 직렬화한다. 일반 apply는 높은 revision만 반영, 동일 명령은 DUPLICATE, 낮으면 STALE이다. 같은 revision의 다른 내용과 아이/원 작성자 변경은 내부 계약 위반 500이며 기본 충돌 예외로 재포장하지 않는다.
- 명시적 정정은 관측한 지도 스냅샷과 잠금 후 상태를 비교한다. 상태가 달라지면 STALE/409로 전체 롤백한다. 일치하면 새 일기 원본으로 교체/삭제하며 손상된 기존 revision이 높아도 사용자 경로를 막지 않는다.

## 원본·불일치·초기 이관

- `diary_entries.location_*`가 원본이고 map 행은 파생 값이다. 양쪽 좌표는 double precision이고 반올림 없이 0 부호만 정규화한다. 원본은 부모의 조건부 버전 갱신에 함께 저장한다.
- 스키마 적용과 초기 백필을 한 시작 트랜잭션에서 수행한다. NULL 위치 모드인 미이관 일기만 처리한다. 정상 ID·아이·작성자·MANUAL 출처가 일치하는 기존 핀은 원본으로 옮기고 지도 revision을 부모 version에 맞춘다. 핀이 없는 미이관 일기는 NONE으로 초기화한다.
- 부모 없는 핀·아이/작성자 충돌·잘못된 좌표/장소명·출처는 보존하고 이관을 중단한다. 전체 검증 후 쓰므로 부분 이관하지 않는다. 이미 초기화한 NONE/MANUAL은 재기동·재적용으로 덮어쓰지 않는다.
- 위치 생략 수정에서 원본·지도 불일치는 ERROR 로그와 500·전체 롤백이다. 명시적 MANUAL/NONE 수정과 일기 삭제는 불일치를 로그에 남기되 원본 기준 정정/삭제를 진행한다. 실제 DB 실패와 관측 경합은 이 경우에도 전체 롤백한다.
- 주소 조회는 map 입력 포트에서 strip·255 UTF-16 단위를 검사하며 공백/초과는 이름 없음으로 반환한다. HTTP·타임아웃·사용 불가 외부 응답만 주소 없이 진행하고 내부 오류는 숨기지 않는다. 기존 연결 1초/응답 2초 제한을 유지한다.

## 남는 범위

GPS 동의·EXIF 후보·AUTO, 가족 멤버십/지도 열람 확대, 프론트 지도·업로더 연결과 직접 UX 검사는 아직 구현하지 않았다. 따라서 복합 #44-S4/S5/S8/S13과 #32-S16/S17/S19 전체를 완료 처리하지 않는다. 시나리오별 실제 검사 위치는 [검증 대응표](../testing-coverage.md)를 따른다.
